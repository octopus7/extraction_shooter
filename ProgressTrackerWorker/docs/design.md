# 데모 진행도 트래커 Worker 설계

## 목적과 범위

데모 이용자의 주요 퀘스트, 장소 도달, 데모 완료를 수집하고 관리자 웹 화면에서 도달 인원과 기록 미수신을 확인한다.
현재 리포의 최상위 `ProgressTrackerWorker/` 폴더 전체를 별도 GitHub 리포 루트로 옮길 수 있어야 한다.
이 작업은 Worker, D1 스키마, 통계 화면과 검증을 구현하며 사용자의 추가 요청에 따라 Unreal 클라이언트 이벤트 전송도 병렬로 구현한다. Unreal 파일은 현재 프로젝트에 남고 ProgressTrackerWorker 폴더만 별도 리포로 옮긴다.

## 확정된 사용자 요구

- Cloudflare Workers + D1을 사용한다.
- 사용자가 별도 리포를 만들고 GitHub 연동과 배포를 직접 수행한다.
- 이 PC에서 Wrangler 인증·실행·배포를 하지 않는다.
- 전송 실패를 위한 재시도, 로컬 대기열, 게임 오류 표시를 구현하지 않는다.
- 앞 단계가 미수신이어도 다음 단계의 기록은 유효하게 저장·집계한다.
- 앞 단계 미수신은 별도 표시하며 미도달이나 비정상 이용자로 분류하지 않는다.
- 기록을 추정해 채워 넣지 않는다.
- 사용자에게 보이는 모든 문자열은 문자열 테이블의 키로 조회한다.

## 배포 방식

폴더 안에 package.json, 잠금 파일, wrangler.jsonc, 소스, 정적 파일, SQL, 테스트와 README를 포함한다.
상위 리포 파일·QuestStudio·Unreal·접근 제한 데이터에 의존하지 않는다.
Cloudflare GitHub Builds에서 테스트 후 배포한다. Cloudflare 측 기본 배포 도구는 Wrangler이며 로컬 로그인과 무관하다.
사용자가 대시보드에서 D1을 생성하고 제공된 SQL을 실행한 뒤 DB 바인딩과 관리자 비밀값을 설정한다.
D1 실제 식별자와 계정 ID, 비밀값은 템플릿에 넣지 않는다. 배포 전에 필요한 설정값을 README에서 명확히 구분한다.
기존 QuestStudio D1이나 Worker는 사용하지 않는다. GitHub 리포 생성·push·외부 배포는 이 작업 범위에 포함하지 않는다.

## 데이터 계약

`POST /api/events`에 단일 이벤트 JSON을 보낸다.

- `eventId`: 전송 이벤트 UUID. 동일 ID 중복 업로드는 한 번만 반영한다.
- `playerId`: 게임에서 생성·유지하는 임의 식별자. SteamID나 이메일은 보내지 않는다.
- `runId`: 한 플레이 진행의 임의 식별자. 새 게임은 새 값을 사용한다.
- `buildId`: 빌드 식별 문자열.
- `dataset`: 최초 버전에서는 demo만 허용한다.
- `checkpointId`: 체크포인트 식별자.
- `category`: start, quest, location, complete 중 하나.
- `playtimeSeconds`: 해당 진행에서 누적된 비음수 플레이 시간.

서버는 수신 시각을 부여한다. 클라이언트가 보낸 닉네임, IP, 자유 텍스트나 이야기 본문은 저장하지 않는다.
길이·형식·요청 크기를 제한하고 SQL 값은 바인딩한다. 알 수 없는 필드와 잘못된 종류·음수 시간은 거절한다.
이벤트 저장은 응답 전에 완료한다. DB 오류는 일반적인 실패 상태를 반환하며 게임은 이를 무시할 수 있다.
앞 단계 기록의 존재는 수신 조건으로 검사하지 않는다.
동일 eventId가 다른 내용으로 재사용되면 기존 기록을 덮어쓰지 않는다.

## 이용자와 진행 집계

`playerId`는 사람 수를 확정하는 값이 아니라 클라이언트에서 제공한 식별자다.
통계 화면은 이를 '고유 이용자 ID 수'로 표시한다. 다른 설치에서 새 ID를 생성하면 별도 집계된다는 제한을 README에 적는다.
새 게임별 진행은 runId로 구분한다. 누락 검사는 같은 playerId, runId, buildId, dataset 범위에서만 수행한다.
빌드별 필터를 제공하고 서로 다른 빌드의 수신 기록을 합쳐 선행 단계가 있다고 판단하지 않는다.

- 단계별 도달 인원: 선택한 빌드 범위에서 해당 단계 기록이 있는 고유 playerId 수.
- 도달률: 해당 범위에서 하나 이상의 이벤트가 수신된 고유 playerId 수를 분모로 한다.
- 시작 기록 인원은 따로 표시한다. 시작 이벤트 누락 때문에 후속 단계 비율이 100%를 넘지 않게 한다.
- 단계별 진행 수: 해당 단계 기록이 있는 고유 진행 수.
- 최초 도달 시간: 같은 진행·단계의 가장 이른 유효 누적 플레이 시간.
- 후속 단계만 기록된 진행도 상세 목록과 합계에 포함한다.
- 페이지네이션과 조회 범위 상한을 두고 전체 원시 기록을 한 응답으로 내려보내지 않는다.

## 체크포인트와 미수신 판정

체크포인트 카탈로그는 폴더 내부 설정 파일로 관리한다.
각 항목에는 ID, 종류, 표시 문자열 키, 표시 순서, 필수 선행 체크포인트 ID 목록을 둔다.
표시 순서만으로 앞 단계 도달을 강제하거나 누락을 추정하지 않는다. 선택 퀘스트·자유 탐색 장소는 필수 선행 단계가 없을 수 있다.
카탈로그에 없는 유효 체크포인트도 저장하고 ID로 표시한다. 별도로 '분류 미등록'을 표시하되 도달 기록은 유지한다.
초기 카탈로그에는 game.start, demo.complete와 확인된 Demo 퀘스트 5개를 제공한다. 퀘스트 키는 quest.<QuestId>, 장소 키는 location.<LocationId> 형식이다. q2의 선행은 q1, q3a/q3b의 선행은 q2, q4의 선행은 q3a와 q3b이며 데모 완료는 q4를 요구한다. 이름이 비어 있는 장소 트리거는 비활성으로 유지한다.
미수신이라는 표기는 전송 실패의 확정 진단이 아니다. 해당 진행에서 선행 기록을 관측하지 못했다는 의미다.
예: A가 B의 필수 선행이고 B만 들어왔으면 B 도달 1건, A 기록 미수신으로 표시한다. A 기록을 자동 생성하지 않는다.
나중에 A가 수신되면 조회 결과에서 미수신 표시는 사라진다.

## API와 관리자 접근

- POST /api/events: 게임 이벤트 수신. 통계 조회 권한을 주지 않는다.
- GET /api/admin/summary: 빌드·단계별 집계.
- GET /api/admin/runs: 페이지 단위 진행 목록과 누락 요약.
- GET /api/admin/run: playerId/runId/buildId/dataset 쿼리로 지정한 진행의 관측된 체크포인트와 필수 선행 기록 미수신.
- GET /api/health: 비밀값·계정 정보가 없는 상태 응답.
- /: 관리자 화면과 로그인 입력.

관리자 API에는 서버 비밀값 ADMIN_TOKEN 인증을 요구하며 설정이 없으면 접근을 거절한다.
입력한 토큰은 페이지 메모리에만 보관하고 URL, localStorage, 로그에 넣지 않는다.
이벤트 수신은 Steam 인증을 요구하지 않는 공개 API로 시작한다. 클라이언트가 보내는 기록은 조작 가능하며 신뢰된 결제·보상 판정에 사용하지 않는다.
수신에 요청 크기 제한과 입력 검증을 적용한다. 관리자 비밀값을 게임에 넣지 않는다.
통계 화면과 관리자 API는 동일 출처로 제공하고 임의 출처에 관리자 CORS를 열지 않는다.

## 화면과 문자열

가벼운 정적 HTML/CSS/JavaScript 화면으로 구현하고 별도 프레임워크 빌드는 요구하지 않는다.
고유 이용자 ID 수, 진행 수, 데모 완료 인원, 단계별 도달 인원과 비율, 기록 미수신 수를 보여준다.
빌드 필터, 진행 목록 페이지 이동과 진행 상세를 제공한다.
한국어 문자열 테이블과 키 조회 함수를 사용한다. 서버 오류는 안정된 오류 코드를 반환하고 화면은 문자열 키로 해석한다.
외부 입력은 textContent 등 안전한 DOM 경로로 표시하며 HTML로 삽입하지 않는다.
로딩, 빈 결과, 인증 실패, 조회 실패 상태를 구분한다. 이는 관리자 화면의 상태이며 게임 전송 실패 UI를 뜻하지 않는다.

## 검증

Wrangler를 실행하지 않는 Node 테스트와 SQLite 기반 검증을 사용한다.

1. A 없이 B 수신: B를 저장하고 집계하며 A를 기록 미수신으로 표시한다.
2. 이벤트 중복·ID 충돌: 중복 인원 증가와 원본 덮어쓰기가 없다.
3. 필수가 아닌 단계 누락: 미수신으로 오인하지 않는다.
4. 다른 진행·빌드 기록: 선행 단계 검사에 섞이지 않는다.
5. 시작 이벤트 누락: 후속 도달을 제외하지 않으며 비율 계산이 정의되어 있다.
6. 잘못된 입력·큰 본문·SQL/XSS 문자열·관리자 무인증: 정의된 거절과 안전한 표시.
7. D1 오류: 성공 응답을 반환하지 않는다.
8. 별도 임시 폴더에 프로젝트만 복사한 뒤 검증: 상위 리포 의존성이 없다.
9. 화면을 로컬에서 열어 필터, 빈 화면, 미수신 표시와 모바일 배치를 확인한다.

실제 Cloudflare 배포와 실서비스 D1 동작은 사용자의 GitHub 연동 후 확인 대상이다.

## Unreal 병렬 작업 범위

- QuestSubsystem::ClaimQuestReward에서 실제 보상 완료 직후 이벤트를 기록한다. 세이브 로드 시 업적 복원 호출은 신규 도달로 전송하지 않는다.
- DemoEndingActor에서 엔딩 표시 후 완료 세이브 삭제 전에 데모 완료 이벤트를 보낸다.
- 현재 확인된 주요 퀘스트 ID는 demo_q1_water_intake_check, demo_q2_clear_water_screen, demo_q3a_repair_valve, demo_q3b_repair_bunker_pipe, demo_q4_todays_reward이다. 병렬/선택 분기는 실제 의존 관계를 확인한 뒤 카탈로그에 반영한다.
- 장소 도달은 기존 LocationId를 사용하며 새 게임별 최초 도달만 전송한다.
- HTTPS 엔드포인트는 프로젝트 설정으로 지정한다. URL이 미설정이면 전송하지 않으며 임의의 실서비스로 보내지 않는다.
- playerId는 설치별로 유지하고 runId는 새 게임 시 발급해 해당 세이브와 함께 저장한다. 이어하기는 같은 runId를 사용한다.
- ID·시간·이미 전송 시도한 단계 저장은 전송 대기열이 아니며 실패 이벤트를 다시 보내지 않는다.
- 추가된 저장 항목과 구버전 세이브의 기본값 처리를 Docs/save_persistence.md에 기록한다.
- Unreal 컴파일과 관련 자동화 검증을 수행하고 프로젝트 지침에 따라 Editor를 연다. 사용자 플레이와 실제 클라우드 도달 검증은 별도로 구분한다.
