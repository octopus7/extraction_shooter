# 호퍼 메카닉 적

## 사용 위치

- 배치용 블루프린트: `/Game/Characters/Hopper/BP_HopperEnemy`
- 전투·경사면 확인 맵: `/Game/Maps/HopperCombatTestMap`
- 모델/애니메이션 설정: `/Game/Characters/Hopper/DA_HopperVisual`
- 편집 원본: `TunaSweeper/SourceArt/Characters/Hopper/Hopper.blend`, 토끼 재수출용 `HopperPilot_UE.blend`
- 원본 메시 출처: 로컬 `HOPPER_03_ArmModules_v5/preview/FitCheck.glb`. 원본 파일은 수정하지 않는다.

기존 레이드 배치 데이터와 사용자 맵은 변경하지 않는다. 테스트 맵은 기존 전투 테스트 게임 모드를 상속한 `BP_HopperTestGameMode`로 테스트 장비 세션을 시작한다.

## 동작

1. 기본 2초 탑승 동작 후 토끼가 콕핏 좌석에 붙는다. 원본 콕핏 기구의 열림/닫힘 트랙을 사용한다.
2. 메카닉 내구도 180 동안 양팔 무기로 공격한다. 토끼 체력과 내구도는 별개이며, 메카닉을 파괴한 공격의 초과 피해는 토끼에게 넘어가지 않는다.
3. 메카닉 파괴 시 기존 로봇 연기 이펙트를 재생한다. 이동을 멈추고 지면·내비게이션·토끼 캡슐·하차 이동 경로를 검사한다. 안전한 위치가 없으면 대기하고 재시도한다. 하차 중에는 공격하지 않는다.
4. 기본 1.4초 하차가 끝나면 토끼가 총으로 공격한다. 기본 탄약은 총 24발이며 예비 탄약이나 무한 재장전은 없다.
5. 마지막 탄약을 사용하면 총을 감추고 기존 적 근접 공격 판정으로 전환한다. 토끼가 죽을 때만 기존 처치·경험치·드롭 처리를 실행한다.

체력·탄약·페이즈·IK 발 위치는 일반 적과 같은 전투 중 임시 상태다. 새 저장 필드나 저장 버전을 추가하지 않는다.

## 팔 교체

`SetArmModule(bLeft, ModuleClass)`로 원본의 L/R 슬롯을 교체한다. true는 원본 `Arm_L`(UE +Y), false는 원본 `Arm_R`(UE -Y)다. null 클래스는 해당 팔을 제거한다. 새 액터 생성 성공 후 이전 액터를 제거하며, 파괴·하차 후에는 교체하지 않는다.

`AHopperArmModule`을 상속한 블루프린트에서 투사체 클래스·피해·발사 간격을 설정하고 `FireWeapon` 이벤트를 재정의할 수 있다. 실제 공격을 생성했을 때만 true를 반환한다. 소유자의 페이즈·아군 관계·조준각·사선과 모듈 쿨다운은 이벤트 앞에서 검사한다.

기본 팔은 원본 팔 외형에 발사구를 더한 투사체 무기다. 새로운 무기의 외형·탄도·효과는 후속 모듈로 추가한다. 자체 외형을 가진 모듈은 `bUseHopperArmVisuals`와 `bShowCannonNozzle`을 끄고 블루프린트에 메시와 발사점을 구성한다. 팔은 본체의 시야 가림과 함께 숨겨진다.

## 보행과 애니메이션

- 지면을 추적한 착지점, 월드 위치에 고정된 지지발, 좌우 교대 스윙, 두 관절 IK로 허벅지·정강이·발을 움직인다.
- 실제 다리 길이에 맞춰 골반을 10cm 낮추고 보행 속도를 제한한다. 기본 이동 속도는 35cm/s이며, 설정한 속도가 관절의 안정적인 도달 범위를 넘으면 더 낮아진다. 회전 중에는 발의 각운동도 고려해 전진 속도를 줄인다.
- 가속도 100cm/s², 제동 감속도 140cm/s², 기본 스윙 0.42초, 발 들기 16cm를 사용한다. 몸통 무게 이동·기울기·착지 후 가라앉음을 적용한다.
- 기본 회전 상한은 35도/초다. 토끼 지상 이동은 160cm/s다.
- 토끼는 Idle, Boarding, Seated, Disembark, Walk, Fire, Melee 7개 제자리 클립을 사용한다. 탑승·하차의 월드 이동은 런타임이 담당한다.
- 모델의 R/L 원본 명칭을 보존한다. UE 축은 전방 +X, 오른쪽 +Y, 위 +Z이고 단위는 cm다. 원본 글자의 좌우가 뒤집히지 않도록 glTF +X를 UE -Y로 변환한다.

## 검증

자동화 필터 `TunaSweeper.Hopper`는 보행 수학, 실제 모델 치수, 페이즈·피해 소유권·탄약·팔 교체·하차 충돌 검사와 PIE 전투/화면 검증을 포함한다. PIE 캡처는 `Saved/Screenshots/Hopper`에 저장한다. 모델 임포트·재로드 결과는 SourceArt의 검증 JSON을 참고한다.
정적 외형 컴포넌트는 메시를 지정하기 전에 충돌과 내비게이션 영향을 끈다. UE 5.7의 메시 설정은 컴포넌트 등록 전에도 내비게이션 자료를 갱신할 수 있으므로, 이 순서를 바꾸면 플레이 시작 후 적 주변에 잘못된 장애물이 남을 수 있다.

### 현재 검증 범위

UE 5.7 에디터 빌드와 호퍼·기존 전투 54개 통합 검사를 통과했다(52개 정상 통과, 2개 기존 경고 포함 통과). PIE 검사는 고정 시간 대신 탑승 완료·내비게이션 생성 완료·시작/목적지 투영, 실제 25cm 이동, 안전한 하차 완료를 기다린다. 준비·이동·하차가 제한 시간 안에 완료되지 않으면 실패를 기록한다. 캐시 로딩으로 프레임이 지연되어도 준비 전에 이동 검사를 시작하지 않는다.

레이드 스폰 프로필·앵커 ID는 아직 연결하지 않았다. BP_HopperEnemy를 레벨에 직접 배치하거나 HopperCombatTestMap에서 확인한다.

## Captain 토끼 모델 교체 (2026-10-07)

현재 파일럿은 사용자가 제공한 `Captain_Outfit_Refined.glb` 모델이다. `/Game/Characters/Hopper/Captain/SK_Captain_Pilot`의 18개 관절과 새 7개 클립을 `DA_HopperVisual`에 연결했다. 기존 탑승·몸통 부착·하차·유한 탄약 사격·근접 전환을 그대로 사용하며 총 부착 변환을 새 손 관절에 맞췄다.

몸체와 군장의 BaseColor, Normal, Metallic/Roughness 6개 텍스처를 실제 512×512 PNG로 다운샘플한 뒤 UE에 임포트했다. 편집 원본은 `TunaSweeper/SourceArt/Characters/Hopper/Captain/CaptainPilot_UE.blend`다. 기존 `Hopper.blend`와 `HopperPilot_UE.blend`는 이전 파일럿이 포함된 초기 원본이므로 현재 토끼 편집에는 Captain 원본을 사용한다.

메시 크기는 약 70cm로 유지했다. 새 무릎 관절, 어깨·발목 경계의 연속 가중치, 정상화된 노멀맵을 검증했다. 새 프로세스 에셋 검사 및 UE 5.7 빌드와 54개 전투 통합 검사가 통과했다(경고 포함 통과 2개, 실패 0개). 재임포트 시 필요한 루트 트랙 보정과 검증 방법은 Captain 폴더의 README를 참고한다.
