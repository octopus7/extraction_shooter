# 호퍼 메카닉 적

## 사용 위치

- 구형 호퍼 블루프린트: `/Game/Characters/Hopper/BP_HopperEnemy`
- 마을·전투 테스트맵용 블루프린트: `/Game/Characters/Hopper/BP_HopperEnemyMk2`
- 전투·경사면 확인 맵: `/Game/Maps/HopperCombatTestMap`
- 모델·애니메이션은 구형의 `DA_HopperVisual`과 Mk2의 `/Game/Characters/Hopper/Mk2/DA_HopperVisualMk2`에서 설정한다.
- 메카 조립 원본은 `TunaSweeper/SourceArt/Characters/Hopper/Hopper.blend`, 토끼대장 편집·재수출 원본은 같은 폴더의 `Captain/CaptainPilot_UE.blend`다.
- 원본 메시 출처: 로컬 `HOPPER_03_ArmModules_v5/preview/FitCheck.glb`. 원본 파일은 수정하지 않는다.

테스트맵은 `BP_HopperTestGameMode`로 테스트 장비 세션을 시작한다. 아웃라이너에 배치된 `Hopper_Mk2`를 볼 수 있는 거리까지 접근하면 토끼대장이 지상에서 탑승하고, 기체 격파 시 좌석이 사출된다.

`HopperCombatTestMap`의 바닥·완경사로·낮은 단차는 `/Game/Environment/HopperTestHangar/Materials/M_HangarLabFloor`를 사용한다. 월드 좌표 기준으로 타일 한 장은 2.4m 정사각형이고, 4.8m마다 매립 점검구와 황색 정비 표식이 반복된다.

### 마을 호퍼 Mk2

`RaidVillage`의 적 배치 7번은 `enemy.village_hopper_boss` 프로필을 통해 `BP_HopperEnemyMk2`를 생성한다. Mk2의 상부 보호 프레임은 토끼 귀 뒤를 지나며, 양쪽 힌지의 잠금쇠가 풀리면 피스톤을 따라 뒤로 젖혀진다. 이어서 앞문이 앞으로 회전하고 내부 발판이 늘어난다. 하차와 사출 때도 같은 개폐 트랙을 사용한다.

프레임과 발판의 편집 원본은 [HopperMk2_GuardAndRamp.blend](../TunaSweeper/SourceArt/Characters/Hopper/Mk2/HopperMk2_GuardAndRamp.blend)다. 타임라인 0번 프레임이 닫힘, 48번이 완전 열림이다. 게임에서는 `DA_HopperVisualMk2`의 `HatchMotion`이 부품별 변환을 재생한다. 완전히 여는 시간은 1.12초로 설정했고, 기본 2초 탑승에서는 처음 0.8초 동안 프레임과 발판이 먼저 움직인다.

토끼대장이 탑승하고 상부 프레임이 닫히면 푸른 실드가 콕핏 앞쪽에서 뒤쪽으로 0.34초 동안 펼쳐진다. 전개를 시작하고 1초가 지나면 밝기가 낮아져 조종사가 비친다. 실드가 켜진 Mk2가 격파되면 카메라가 접근하는 첫 프레임부터 중앙에 금이 가고, 토끼가 레버를 당기는 동안 세 차례 밝아졌다 어두워지며 균열이 바깥으로 번진다. 실드가 깨지는 순간 유리 조각과 스파크가 튀고, 폭발로 그을린 상부 가로바와 양쪽 팔이 한 덩어리로 뒤쪽 위로 튕겨 나간다.

### 플레이 중 탑승과 사출 카메라

마을에서는 인터페이스 설정의 ‘전투 진입 연출 하루 한 번 보기’가 기본으로 켜져 있다. 마을 탑승을 마치면 기기의 현지 날짜를 기록하고 같은 날 다음 조우에서는 바로 메카 전투로 들어간다. 옵션을 끄면 매번 탑승을 보여준다. 테스트맵은 설정과 날짜에 관계없이 매번 재생한다. 사출 연출은 이 설정과 독립적으로 동작한다.

Mk2의 `DA_HopperVisualMk2`에서 `Use Encounter Camera`를 켠다. 토끼대장은 기체 앞에서 기다린다. 플레이어의 시야 거리·방향 안에 있고 사이에 가림막이 없으며 현재 플레이 화면에 조종석이 들어오면 한 번 탑승한다. 이미 탑승한 상태로 배치한 개체는 바로 메카 전투를 시작한다.

탑승은 기체 전방 사선에서 토끼와 발판을 함께 잡는 컷으로 시작한다. 토끼가 올라가면서 카메라가 조종석에 가까워지고, 프레임이 닫혀 실드가 전개된 뒤 원래 플레이 시점으로 돌아간다. 사출은 당시 플레이 시점에서 0.22초에 걸쳐 조종석으로 전환한다. 카메라는 토끼의 얼굴과 오른손을 가까이 잡고, 레버가 끝까지 내려간 순간부터 실드와 기체가 함께 보이도록 빠진다. 좌석의 초기 상승을 따라간 뒤 0.45초에 걸쳐 플레이 시점으로 돌아간다.

두 연출 모두 시작 프레임부터 복귀 블렌드가 끝날 때까지 입력을 잠근다. 이동 속도와 이동 요청, 연사·조준·질주 등의 눌림 상태를 해제한다. 도중에 눌렀다 뗀 키는 소모하고, 복귀 시 계속 누른 키는 뗀 뒤 새로 눌러야 반응한다. 게임패드 축은 중립을 한 번 거쳐야 한다. `TunaSweeper.Hopper.Play.EncounterCameraAndInput`이 실제 테스트맵에서 시야 가림, 두 카메라 전환, 키·스틱 복귀와 탑승 도중 격파를 검증한다.

## 동작

1. 기본 2초 탑승 동작 후 토끼가 콕핏 좌석에 붙는다. 원본 콕핏 기구의 열림/닫힘 트랙을 사용한다.
2. 메카닉 내구도 180 동안 양팔 무기로 공격한다. 토끼 체력과 내구도는 별개이며, 메카닉을 파괴한 공격의 초과 피해는 토끼에게 넘어가지 않는다.
3. 기본 `EndCombatOnMechDestruction=true`에서는 메카닉 내구도 0 즉시 기존 적 처치·경험치·드롭 경로를 한 번 실행한다. Mk2의 좌석은 프레임이 분리된 직후 수직으로 사출되며 앞문과 사다리는 계속 열린다. 원형 호퍼는 앞문이 열린 뒤 좌석이 앞으로 슬라이드해 사출된다. 조종석이 열린 비전투 잔해는 남고 공격·이동·추가 피해는 중단된다.
4. 퀘스트는 메카닉을 파괴한 플레이어의 처치 알림으로 진행하며, 보상 자동 수령은 하지 않는다. 일반 적은 기존 사망 연출과 제거 동작을 유지한다.
5. 이전 2페이즈 동작을 사용하는 별도 변형은 `EndCombatOnMechDestruction=false`로 명시한다. 이 경우 안전한 하차 검사 → 유한 탄약 사격 → 근접 전투 → 조종사 최종 처치의 기존 흐름을 사용한다. 기존 하차/PIE 회귀 검사는 이 옵션을 명시한다.

체력·탄약·페이즈·IK 발 위치는 일반 적과 같은 전투 중 임시 상태다. 새 저장 필드나 저장 버전을 추가하지 않는다.

### 격파 후 좌석 사출

붉은 사출 레버는 좌석 등받이 오른쪽에서 손이 닿는 위치에 고정돼 있다. Mk2가 격파되면 카메라가 0.22초 만에 조종석에 도달한다. 이때 토끼대장이 급히 좌우를 살피고 카메라가 오른손 쪽으로 다가온다. 격파 후 0.78초에 토끼가 그립을 잡고 0.82~1.00초에 앞으로 당겨 내린다. 레버가 끝까지 내려간 프레임에 실드가 깨지고 프레임과 좌석이 함께 분리된다. 카메라는 곧바로 빠지면서 날아가는 보호대와 상승하는 좌석을 담는다. 실드가 전개되기 전 격파되면 같은 레버 동작 후 프레임과 좌석이 분리된다. `DA_HopperVisualMk2`의 `EjectionPull`이 조종사 애니메이션, 좌석 기준 레버 궤적, 사출 시점을 함께 지정한다.

Mk2의 `DA_HopperVisualMk2`에서 `EjectionGuardParts`는 가로바와 양쪽 팔을 지정한다. 세 부품의 볼록 충돌체를 하나의 Chaos 강체로 묶어 날리며, 측면 고정부와 유압 실린더는 차체에 남는다. 프레임이 뒤쪽으로 날아가는 동시에 조종사·좌석·조작부가 그 자리에서 월드 수직으로 상승한다. 탑승이 중단돼 좌석이 레일 중간이나 사다리 상단에 있을 때도 그 위치에서 발사된다. 좌석 분리 약 0.16초 뒤 빈 차체가 발화하고, 약 8초에 걸쳐 도장이 바랜다.

원형 호퍼는 `HopperPresentationComponent`의 `Hopper|Ejection`에서 문 열림 시간(기본 0.65초), 슬라이드 시간(0.55초)·거리(90cm), 상승 시간(3초)과 전방·상승 속도·상승 가속도를 조절한다. 문이 완전히 열린 뒤 좌석과 조종사가 함께 전방으로 빠져나와 상승한다.

두 갈래 발광 로켓 화염은 좌석 아래에서 나오며, 흰 연기는 월드 위치에 남아 1.6초 동안 퍼지고 사라진다. 기존 발광 머터리얼과 연기 텍스처를 재사용하며, 흰 연기 전용 `M_HopperEscapeSmoke`를 추가했다. 두 머터리얼은 BP에서 교체할 수 있다. 프레임이 길어져도 궤적을 따라 연기를 배치하고, 제한된 컴포넌트 풀을 재사용한다. 탈출 후 좌석과 조종사를 숨기고 연기가 끝나면 효과 컴포넌트 및 연출 틱을 정리한다. 이 연출은 처치 알림을 지연하거나 두 번째 전투를 시작하지 않는다.

`TunaSweeper.Hopper.Combat.SeatEjection`은 단계 순서·부착·분리·상승·종료를 검사한다. `TunaSweeper.Hopper.Play.SeatEjection`은 실제 PIE에서 `Saved/Screenshots/Hopper/Ejection_00.png`부터 `Ejection_05.png`까지 단계별 화면을 저장한다.

## 팔 교체

`SetArmModule(bLeft, ModuleClass)`로 원본의 L/R 슬롯을 교체한다. true는 원본 `Arm_L`(UE +Y), false는 원본 `Arm_R`(UE -Y)다. null 클래스는 해당 팔을 제거한다. 새 액터 생성 성공 후 이전 액터를 제거하며, 파괴·하차 후에는 교체하지 않는다.

`AHopperArmModule`을 상속한 블루프린트에서 투사체 클래스·피해·발사 간격을 설정하고 `FireWeapon` 이벤트를 재정의할 수 있다. 실제 공격을 생성했을 때만 true를 반환한다. 소유자의 페이즈·아군 관계·조준각·사선과 모듈 쿨다운은 이벤트 앞에서 검사한다.

기본 팔은 원본 팔 외형에 발사구를 더한 투사체 무기다. 새로운 무기의 외형·탄도·효과는 후속 모듈로 추가한다. 자체 외형을 가진 모듈은 `bUseHopperArmVisuals`와 `bShowCannonNozzle`을 끄고 블루프린트에 메시와 발사점을 구성한다. 팔은 본체의 시야 가림과 함께 숨겨진다.

## 보행과 애니메이션

- 지면을 추적한 착지점, 월드 위치에 고정된 지지발, 좌우 교대 스윙, 두 관절 IK로 허벅지·정강이·발을 움직인다.
- 실제 다리 길이에 맞춰 골반을 10cm 낮추고 보행 속도를 제한한다. 기본 이동 속도는 35cm/s이며, 설정한 속도가 관절의 안정적인 도달 범위를 넘으면 더 낮아진다. 회전 중에는 발의 각운동도 고려해 전진 속도를 줄인다.
- 가속도 100cm/s², 제동 감속도 140cm/s², 기본 스윙 0.42초, 발 들기 16cm를 사용한다. 몸통 무게 이동·기울기·착지 후 가라앉음을 적용한다.
- 기본 회전 상한은 35도/초다. 토끼 지상 이동은 160cm/s다.
- 토끼는 Idle, Boarding, Seated, Disembark, Walk, Fire, Melee 7개 제자리 클립을 사용한다. 탑승·하차의 월드 이동은 런타임이 담당한다.
- 모델의 R/L 원본 명칭을 보존한다. UE 축은 전방 +X, 오른쪽 +Y, 위 +Z이고 단위는 cm다. 원본 글자의 좌우가 뒤집히지 않도록 glTF +X를 UE -Y로 변환한다.

## 검증

자동화 필터 `TunaSweeper.Hopper`는 보행 수학, 실제 모델 치수, 페이즈·피해 소유권·탄약·팔 교체·하차 충돌 검사와 PIE 전투/화면 검증을 포함한다. PIE 캡처는 `Saved/Screenshots/Hopper`에 저장한다. 모델 임포트·재로드 결과는 SourceArt의 검증 JSON을 참고한다.
정적 외형 컴포넌트는 메시를 지정하기 전에 충돌과 내비게이션 영향을 끈다. UE 5.7의 메시 설정은 컴포넌트 등록 전에도 내비게이션 자료를 갱신할 수 있으므로, 이 순서를 바꾸면 플레이 시작 후 적 주변에 잘못된 장애물이 남을 수 있다.

### 현재 검증 범위

UE 5.7 에디터 빌드와 호퍼·기존 전투 54개 통합 검사를 통과했다(52개 정상 통과, 2개 기존 경고 포함 통과). PIE 검사는 고정 시간 대신 탑승 완료·내비게이션 생성 완료·시작/목적지 투영, 실제 25cm 이동, 안전한 하차 완료를 기다린다. 준비·이동·하차가 제한 시간 안에 완료되지 않으면 실패를 기록한다. 캐시 로딩으로 프레임이 지연되어도 준비 전에 이동 검사를 시작하지 않는다.

구형 외형과 별도로 비교할 때는 `BP_HopperEnemy`를 사용한다.

## Captain 토끼 모델 교체 (2026-10-07)

현재 파일럿은 사용자가 제공한 `Captain_Outfit_Refined.glb` 모델이다. `/Game/Characters/Hopper/Captain/SK_Captain_Pilot`의 18개 관절과 새 7개 클립을 `DA_HopperVisual`에 연결했다. 기존 탑승·몸통 부착·하차·유한 탄약 사격·근접 전환을 그대로 사용하며 총 부착 변환을 새 손 관절에 맞췄다.

몸체와 군장의 BaseColor, Normal, Metallic/Roughness 6개 텍스처를 실제 512×512 PNG로 다운샘플한 뒤 UE에 임포트했다. `Hopper.blend`는 `Captain/CaptainPilot_UE.blend`의 메시·골격·착석 클립을 상대 경로로 연결한다. 조립 원본을 열면 게임과 같은 좌석 위치에 토끼대장이 앉아 있다.

메시 크기는 약 70cm로 유지했다. 새 무릎 관절, 어깨·발목 경계의 연속 가중치, 정상화된 노멀맵을 검증했다. 새 프로세스 에셋 검사 및 UE 5.7 빌드와 54개 전투 통합 검사가 통과했다(경고 포함 통과 2개, 실패 0개). 재임포트 시 필요한 루트 트랙 보정과 검증 방법은 Captain 폴더의 README를 참고한다.
## 메카 전용 피격 및 높이 조준 (2026-10-18)

메카의 몸체·해치·다리·교체형 팔은 각 정적 메시의 로컬 경계에 맞춘 별도 박스 판정을 사용한다. 박스는 외형 변환을 따라가며 Visibility와 Projectile 질의만 막고, 이동 캡슐 크기와 Pawn 이동 충돌은 바꾸지 않는다. 팔 판정도 메카 소유이므로 피해·화상·처치 처리가 본체로 전달된다. 팔 제거 시 판정을 정리하며 메카 파괴 시 모든 전용 판정을 끈다.

커서가 살아 있는 메카의 전용 판정에 맞았을 때만 실제 표면의 높이와 XY로 조준·투사체·레이저 방향을 맞춘다. 일반 적과 빈 공간 사격은 기존 총구 높이의 수평 방향을 유지한다. 선택형 파일럿 전투에서는 기존 캡슐 투사체 판정을 복구한다.

UE 5.7 에디터 빌드 및 Hopper.Combat, Quest.EnemyClass, Combat.Burn 자동 테스트 17개 통과. 새 HitVolumesAndScopedAim 검사는 실제 충돌 질의, 팔 피격의 본체 피해 전달, 메카 전용 3D 발사 방향, 일반 적 수평 발사, 파괴 후 판정 해제를 확인한다. 플레이 화면에서의 수동 조작 검증은 별도다.
