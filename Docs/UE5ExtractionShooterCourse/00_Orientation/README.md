# 00. 오리엔테이션

## 학습 목표

- 익스트랙션 슈터의 기본 루프를 벙커, 출동, 탐색, 전투, 루팅, 탈출, 정산으로 나눈다.
- 강의 문서와 실제 개발 문서의 역할 차이를 이해한다.
- `TunaSweeper`를 완성 예시가 아니라 기능 분해 참고 자료로 읽는 방법을 정한다.

## 강의 흐름

1. 장르 구조를 먼저 설명한다.
2. `BunkerMap`과 `RaidMap`의 역할을 분리한다.
3. 플레이어가 한 번의 레이드에서 겪는 상태 변화를 시간순으로 정리한다.
4. 강의에서 다룰 시스템을 모듈 단위로 나눈다.

## 핵심 개념

- 벙커는 준비, 상점, 창고, 제작, NPC, 퀘스트를 담당하는 안전 구역이다.
- 레이드는 전투, 탐색, 루팅, 위험, 탈출 판단이 일어나는 위험 구역이다.
- 익스트랙션 슈터의 재미는 "얼마나 더 가져갈 것인가"와 "언제 돌아갈 것인가" 사이의 긴장으로 만든다.
- 구현은 한 번에 완성하지 않고 이동, 상호작용, 인벤토리, 전투, 저장 순서로 쌓는다.

## 기준 프로젝트에서 볼 지점

- `TunaSweeper/Content/Data`의 JSON 파일은 게임 규칙을 데이터로 밀어낸 예시다.
- `TunaSweeper/Source/TunaSweeper/Private/Subsystem`은 기능별 런타임 소유자를 나눈 예시다.
- `Docs/game_conventions.md`는 좌표, 단위, 재화 같은 실제 개발 기준을 담는다.
- `Docs/save_persistence.md`는 어떤 상태가 저장되어야 하는지 추적한다.

## 실습

- 프로젝트 폴더에서 `TunaSweeper.uproject`, `Source`, `Content/Data`, `Docs`의 역할을 확인한다.
- 벙커와 레이드에서 필요한 기능을 각각 5개씩 적어 본다.
- 강의 중 직접 구현할 최소 루프를 "출동 -> 루팅 -> 탈출 -> 저장" 한 줄로 요약한다.

## 확인 포인트

- 강의 자료의 단순화된 설명을 실제 개발 규칙으로 착각하지 않는다.
- 장르 루프를 시스템 이름이 아니라 플레이어 경험 기준으로 설명할 수 있다.
- 이후 장에서 각 시스템이 전체 루프의 어느 위치에 들어가는지 연결할 수 있다.
