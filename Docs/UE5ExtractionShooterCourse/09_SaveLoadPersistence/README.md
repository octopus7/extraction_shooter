# 09. 저장과 영속성

## 학습 목표

- 저장해야 하는 상태와 저장하면 안 되는 런타임 상태를 구분한다.
- 세이브 슬롯, 버전, 마이그레이션, 저장 타이밍의 중요성을 이해한다.
- 익스트랙션 장르에서 성공/실패 결과가 저장 데이터에 미치는 영향을 설명한다.

## 강의 흐름

1. `SaveGame` 객체가 소유할 데이터를 분류한다.
2. `GameInstance`가 런타임 상태와 저장 상태 사이를 중재하는 방식을 설명한다.
3. 레벨 이동, 사망/후송, 메뉴 복귀, UI 종료 시점의 저장 타이밍을 비교한다.
4. 저장 버전과 이전 세이브 호환 처리의 필요성을 설명한다.

## 핵심 개념

- 저장 데이터는 플레이어가 나갔다 와도 유지되어야 하는 상태만 포함한다.
- 현재 맵의 임시 Actor 포인터나 UI 상태는 그대로 저장하지 않는다.
- 아이템 인스턴스, 슬롯 배열, 퀘스트 진행, 재화, 창고, 월드 진행은 대표적인 영속 상태다.
- 레이드 중 누적 경험치처럼 성공할 때만 확정되는 값은 임시 상태로 관리한다.
- 저장 타이밍은 기술 문제이면서 동시에 플레이어 신뢰 문제다.

## 실습

- 새 기능을 하나 정하고 저장해야 할 필드, 저장하지 말아야 할 필드, 복원 시 계산할 필드를 분류한다.
- 세이브 버전이 올라갈 때 필요한 기본값 처리 절차를 적는다.
- 아이템 이동 UI에서 즉시 저장과 지연 저장의 장단점을 비교한다.

## 확인 포인트

- 저장 데이터에 Actor 참조를 직접 넣으면 안 되는 이유를 설명할 수 있다.
- 세이브 파일은 현재 코드보다 오래 살아남는다는 점을 이해한다.
- 저장 문서를 코드 변경과 같이 갱신해야 하는 이유를 설명할 수 있다.
