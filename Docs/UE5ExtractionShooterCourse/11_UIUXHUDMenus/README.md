# 11. UI, HUD, 메뉴

## 학습 목표

- HUD, 인벤토리, 상점, 창고, 작업대, 퀘스트, 지도 UI의 책임을 나눈다.
- UI가 게임 상태를 소유하지 않고 표시와 입력 라우팅을 맡는 구조를 이해한다.
- 익스트랙션 슈터에서 정보량과 조작 효율을 균형 있게 배치하는 방법을 배운다.

## 강의 흐름

1. 게임플레이 HUD와 메뉴형 패널을 구분한다.
2. 인벤토리 모드와 외부 컨테이너 패널이 같은 슬롯/아이템 데이터를 다루는 방식을 설명한다.
3. 퀘스트, 토스트, 상호작용 마커, 추출 진행 UI처럼 짧은 피드백 UI를 분리한다.
4. 입력 모드와 저장 타이밍이 UI 종료 시점과 연결되는 지점을 설명한다.

## 핵심 개념

- HUD는 플레이 중 계속 필요한 상태를 보여준다.
- 메뉴 패널은 플레이어 입력을 잠시 전환하고 복잡한 조작을 처리한다.
- 인벤토리 UI는 아이템 데이터의 복사본이 아니라 현재 슬롯 상태의 표현이다.
- 상점, 창고, 루트 컨테이너는 모두 "외부 컨테이너와 플레이어 컨테이너 사이의 이동"으로 볼 수 있다.
- UI 전환 페이드, 토스트, 퀘스트 알림은 게임 규칙을 플레이어가 인지하게 만드는 장치다.

## 실습

- 플레이 중 항상 보일 HUD 요소와 필요할 때만 여는 패널을 분류한다.
- 아이템 슬롯 드래그 앤 드롭이 호출해야 할 게임 로직을 순서로 적는다.
- 추출 진행 UI에서 표시해야 할 최소 정보 3개를 정한다.

## 확인 포인트

- UI가 저장 데이터의 원본을 직접 소유하면 안 되는 이유를 설명할 수 있다.
- 입력 모드가 바뀌면 게임플레이 조작과 UI 조작이 충돌할 수 있음을 이해한다.
- 정보가 많은 장르일수록 UI 상태 전환 규칙이 중요하다는 점을 설명할 수 있다.
