# 14. 테스트, 밸런싱, 패키징

## 학습 목표

- 기능 구현 후 확인해야 할 테스트 단계를 정리한다.
- 전투, 루팅, 경제, 저장, UI 밸런싱을 데이터 관점으로 다룬다.
- 패키징과 실행 검증이 개발 완료와 별개의 단계임을 이해한다.

## 강의 흐름

1. 작은 기능 단위의 수동 테스트 체크리스트를 만든다.
2. 레이드 루프 전체를 관통하는 스모크 테스트를 설계한다.
3. 피해량, 체력, 아이템 가격, 보상, 추출 시간 같은 밸런스 값을 데이터로 조정한다.
4. 패키징 전 빌드, 쿠킹, 실행, 저장/로드 확인 절차를 설명한다.

## 핵심 개념

- 익스트랙션 슈터 테스트는 한 기능만 보는 것이 아니라 "준비 -> 출동 -> 루팅 -> 전투 -> 탈출 -> 저장" 전체를 반복해야 한다.
- 밸런스 값은 코드보다 데이터에 둘수록 조정과 비교가 쉽다.
- 저장/로드 테스트는 성공 경로뿐 아니라 실패, 강제 종료, 이전 버전 데이터까지 확인해야 한다.
- 패키징은 에디터에서 잘 되는 것과 별개로 콘텐츠 참조, 모듈 의존성, 저장 경로 문제가 드러나는 단계다.

## 실습

- 10분 안에 실행할 수 있는 레이드 루프 스모크 테스트를 작성한다.
- 전투 밸런스 표를 만들고 피해량, 체력, 탄약, 방어 수치를 서로 연결한다.
- 패키징 전 확인할 항목을 빌드, 콘텐츠, 저장, UI, 입력, 로그로 나눈다.

## 확인 포인트

- 테스트는 버그 찾기뿐 아니라 설계 가정 검증이라는 점을 설명할 수 있다.
- 밸런스 조정이 저장 데이터와 퀘스트 보상에 영향을 줄 수 있음을 이해한다.
- 에디터 실행 성공과 패키지 실행 성공을 별도로 확인해야 하는 이유를 설명할 수 있다.
