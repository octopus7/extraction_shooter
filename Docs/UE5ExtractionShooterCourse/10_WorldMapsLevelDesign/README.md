# 10. 월드, 맵, 레벨 디자인

## 학습 목표

- 벙커와 레이드 맵의 디자인 목표를 구분한다.
- 좌표, 거리, 방향 기준이 레벨 배치와 UI 지도에 미치는 영향을 이해한다.
- 데이터 기반 런타임 배치와 에디터 직접 배치의 차이를 설명한다.

## 강의 흐름

1. `+X` 북쪽, UE cm 단위, 화면 12시 방향 기준을 설명한다.
2. 벙커는 안전한 허브, 레이드는 위험과 보상의 공간으로 나눈다.
3. 런타임 스폰 데이터로 상호작용 Actor와 적을 배치하는 흐름을 설명한다.
4. 지도 캡처, 마커, 월드 진행 오브젝트가 레벨 디자인과 연결되는 방식을 설명한다.

## 핵심 개념

- 레벨 디자인은 예쁘게 배치하는 작업뿐 아니라 플레이어 동선, 위험, 보상, 복귀 지점을 설계하는 작업이다.
- 좌표 기준이 문서와 코드에서 흔들리면 맵 마커, 스폰, 카메라 설명이 모두 어긋난다.
- 런타임 스폰은 같은 맵 자산을 유지하면서 데이터로 배치를 바꾸기 좋다.
- 월드 진행 오브젝트는 플레이어가 수리, 해금, 개방한 상태를 저장 데이터와 연결한다.
- 지도 이미지는 실제 월드 좌표를 플레이어가 이해할 수 있는 2D 정보로 변환하는 도구다.

## 실습

- 간단한 레이드 맵을 시작 지점, 루트 지점, 위험 지점, 추출 지점으로 나눈다.
- 월드 좌표 3개를 지도 UI 좌표로 옮긴다고 가정하고 필요한 기준값을 적는다.
- 직접 배치할 Actor와 JSON으로 스폰할 Actor를 구분한다.

## 확인 포인트

- 맵 디자인 문서에 방향과 단위 기준을 먼저 적어야 하는 이유를 설명할 수 있다.
- 런타임 스폰 데이터가 레벨 반복 제작 속도에 주는 장점을 이해한다.
- 지도 UI는 미니맵 이미지가 아니라 월드와 데이터의 투영 결과라는 점을 설명할 수 있다.
