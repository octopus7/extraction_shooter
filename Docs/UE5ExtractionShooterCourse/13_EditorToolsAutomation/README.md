# 13. 에디터 툴과 자동화

## 학습 목표

- 반복 제작을 줄이기 위해 에디터 모듈과 제작 도구를 사용하는 이유를 이해한다.
- 런타임 기능과 에디터 전용 자동화를 분리한다.
- 지도 캡처, 지형 생성, 메시 조합, 사운드 도구 같은 내부 제작 툴의 구조를 배운다.

## 강의 흐름

1. 에디터 모듈이 런타임 모듈과 다른 빌드/배포 대상을 가진다는 점을 설명한다.
2. CallInEditor, Details 커스터마이즈, Slate 탭, ToolMenus 진입점을 비교한다.
3. 데이터나 에셋을 생성하는 도구는 반복 제작 비용을 줄이는 데 쓰인다는 점을 설명한다.
4. 자동화 명령은 결과 검증과 로그 확인까지 포함해야 한다는 점을 강조한다.

## 핵심 개념

- 에디터 툴은 게임 중 플레이어가 쓰는 기능이 아니라 개발자가 제작 효율을 높이기 위한 기능이다.
- 런타임 코드에 에디터 전용 의존성이 섞이면 패키징과 유지보수에 문제가 생긴다.
- 지도 캡처, 절차 지형, 부시 메시 빌더 같은 도구는 결과물을 사람이 검수할 수 있어야 한다.
- 자동화는 "한 번 실행됐다"가 아니라 "예상 결과가 저장되고 오류가 없다"까지 확인해야 끝난다.

## 실습

- 제작자가 반복해서 하는 작업 3개를 골라 에디터 툴 후보로 분류한다.
- 에디터 메뉴 진입점과 도킹 탭 UI가 필요한 경우를 구분한다.
- 자동화 명령을 만들 때 입력, 출력, 검증 로그를 표로 정리한다.

## 확인 포인트

- 에디터 모듈은 게임 패키지의 플레이 기능이 아니라는 점을 설명할 수 있다.
- 도구가 결과를 자동 생성하더라도 사람이 검수할 지점이 필요하다는 점을 이해한다.
- 강의용 도구 설명이 실제 프로젝트 도구 변경으로 자동 이어지면 안 되는 이유를 설명할 수 있다.
