# 06. 전투, 무기, 데미지

## 학습 목표

- 무기, 투사체, 탄약, 피해, 리코일을 별도 책임으로 나눈다.
- 플레이어와 적이 같은 피해 처리 규칙을 어느 정도 공유해야 하는지 이해한다.
- 전투 피드백을 수치 처리, 이펙트, UI 표시로 나누어 설계한다.

## 강의 흐름

1. 무기 컴포넌트가 장착 무기와 발사 요청을 관리하는 방식을 설명한다.
2. 무기 Actor와 투사체 Actor의 책임을 분리한다.
3. 피해 계산은 장비, 탄약, 대상 방어 수치를 반영한다.
4. 명중 이펙트, 피해 숫자, 재장전 링 같은 피드백을 UI와 이펙트로 분리한다.

## 핵심 개념

- 무기는 발사 가능 여부, 탄약, 연사 간격, 확산, 리코일을 관리한다.
- 투사체는 이동, 충돌, 피해 전달, 충돌 이펙트를 담당한다.
- 피해 계산은 "기본 피해 -> 탄약 보정 -> 방어 보정 -> 실제 적용" 순서로 정리할 수 있다.
- 리코일은 커서 좌표를 직접 바꾸기보다 조준 표시와 발사 기준 오프셋으로 표현할 수 있다.
- 연습용 허수아비는 전투 피드백을 검증하기 좋은 안전한 테스트 대상이다.

## 실습

- 단발 무기의 발사 조건을 상태 목록으로 적는다. 예: 장착됨, 탄약 있음, 쿨다운 종료, 입력 가능.
- 투사체가 충돌했을 때 처리 순서를 의사 코드로 쓴다.
- 피해량 표시가 벽에는 뜨지 않고 체력 있는 대상에만 뜨도록 조건을 정한다.

## 확인 포인트

- 무기 Actor와 캐릭터 전투 컴포넌트를 분리하는 이유를 설명할 수 있다.
- 탄약과 무기 피해를 하나의 숫자로만 처리하면 확장성이 떨어지는 이유를 이해한다.
- 전투 피드백이 실제 피해 처리와 동기화되어야 하는 이유를 설명할 수 있다.
