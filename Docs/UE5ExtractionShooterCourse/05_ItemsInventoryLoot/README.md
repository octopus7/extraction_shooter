# 05. 아이템, 인벤토리, 루팅

## 학습 목표

- 아이템 정의 데이터와 플레이어가 소유한 아이템 인스턴스를 구분한다.
- 인벤토리, 장비, 보조 가방, 퀵슬롯, 창고, 상점, 루트 컨테이너의 역할을 나눈다.
- 익스트랙션 장르에서 아이템이 레이드 성공/실패와 어떻게 연결되는지 이해한다.

## 강의 흐름

1. 아이템 정의와 아이템 인스턴스의 차이를 설명한다.
2. 슬롯 배열과 아이템 UID 참조 구조를 설명한다.
3. 루팅, 구매, 판매, 제작, 보관이 모두 같은 소유권 변경 문제임을 설명한다.
4. 레이드 중 획득한 아이템이 탈출/후송 결과에 따라 어떻게 보존되는지 연결한다.

## 핵심 개념

- 아이템 정의는 이름, 아이콘, 가격, 카테고리, 스택 가능 여부 같은 정적 데이터다.
- 아이템 인스턴스는 UID, 수량, 장착 파츠, 장전 탄약처럼 플레이어마다 달라지는 데이터다.
- 슬롯은 아이템 자체를 복사하지 않고 UID를 참조한다.
- 인벤토리 UI의 드래그 앤 드롭은 결국 슬롯 배열과 아이템 인스턴스 목록을 일관되게 바꾸는 작업이다.
- 벙커 창고는 실패해도 보존되는 안전 저장소이고, 레이드 인벤토리는 실패 시 손실될 수 있는 위험 저장소다.

## 실습

- "통조림 참치" 같은 소비 아이템 정의와 플레이어가 가진 아이템 인스턴스를 따로 작성해 본다.
- 5칸 단위 슬롯 UI에서 실제 용량과 표시 패딩 칸을 분리해 생각한다.
- 상자에서 아이템을 꺼내 인벤토리로 옮기는 과정을 UID 이동 관점으로 정리한다.

## 확인 포인트

- 같은 아이템 정의를 가진 인스턴스가 여러 개 존재할 수 있는 이유를 설명할 수 있다.
- 저장 데이터에서 슬롯 배열과 아이템 인스턴스 목록이 함께 유지되어야 하는 이유를 이해한다.
- 상점 판매, 창고 이동, 작업대 제작이 모두 아이템 소유권 변경이라는 점을 설명할 수 있다.
