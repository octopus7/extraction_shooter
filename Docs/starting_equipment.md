# 시작 지급 장비와 레이저 설정

## 시작 지급 장비

`TunaSweeper/Content/Data/DemoStartingLoadout.json`에서 새 데모 세이브의 지급 장비를 설정한다. 전투 실험실의 임시 기본 장비도 같은 파일을 읽는다. 기존 세이브와 Main의 초기화 정책은 변경하지 않는다.

```json
{
  "selected_weapon_slot": 1,
  "equipment": [
    {
      "slot_index": 0,
      "item_id": 1002,
      "attachments": [2006],
      "loaded_ammo": { "item_id": 2002, "quantity": 30 }
    }
  ],
  "inventory": [
    { "slot_index": 0, "item_id": 2002, "quantity": 30 }
  ]
}
```

- `equipment`: 장착할 아이템 목록. 각 행은 아이템 1개다. `slot_index`는 0부터 시작하며 총기 1, 총기 2, 근접, 머리, 신체, 얼굴, 이어폰, 가방 순서다.
- `attachments`: 부착물 아이템 ID 목록. 생략할 수 있으며 각 부착물의 `attachment_slot_tag`에 배치한다. 같은 부착 슬롯에 두 개를 지정할 수 없다.
- `loaded_ammo`: 장전할 탄약의 ID와 수량. 생략하면 비장전 상태다. 수량은 0 이상이며 부착물 보정을 포함한 탄창 용량 이하여야 한다.
- `inventory`: 인벤토리에 넣을 아이템 목록. 슬롯 번호는 0부터 시작하고 `quantity`는 1부터 해당 아이템의 최대 스택까지다. 많은 수량은 여러 슬롯에 나누어 적는다. 가방의 확장 용량은 장착 장비를 적용한 뒤 계산한다.
- `selected_weapon_slot`: 처음 선택할 무기. `1`은 총기 1, `2`는 총기 2, `0`은 근접무기다. 선택한 슬롯에 장비가 있어야 한다.
- 모든 ID는 `ItemTable.json`에 존재해야 하며 슬롯·부착물·탄약 호환 규칙을 만족해야 한다. 슬롯과 수량에는 소수나 음수를 사용할 수 없다.
- 필수 항목 누락, 잘못된 ID, 중복 슬롯, 호환 실패, 수량·용량 초과가 있으면 지급 전체를 취소한다. 잘못된 설정을 기본 아이템으로 대체하지 않는다.

현재 기본 구성은 소총·레이저 사이트·장전탄 30발·예비탄 30발이다. 지급 목록을 바꾸어도 기존 세이브의 아이템을 교체하거나 추가 지급하지 않는다. 이 파일은 기존 `Data` 디렉터리 스테이징 설정으로 빌드에 포함된다.

전투 실험실은 장착 총기에 설정된 탄약 종류마다 연습용 예비탄 300발을 추가로 지급한다. 두 총기가 같은 탄약을 사용하면 한 번만 추가한다. 탄약이 지정되지 않은 총기나 근접무기만 있는 구성에는 추가 탄약을 지급하지 않는다. 이 보급은 새 데모 세이브의 지급량에는 영향을 주지 않는다.

## 레이저 사이트

레이저 기능을 제공하는 부착물의 `ItemTable.json` 정의에 `"provides_laser_sight": true`를 지정한다. 생략 시 `false`다.

레이저는 현재 선택한 총기의 `attachment.slot.tactical` 슬롯에 실제로 장착된 부품에서만 작동한다. 해당 무기에 전술 부착 슬롯이 있고 부품의 `compatible_weapon_type_tags`와 호환되어야 한다. 호환 태그 목록이 비어 있으면 기존 부착물 규칙대로 무기 종류를 제한하지 않는다.

기존 레이저 사이트의 ID는 유지한다. 새 레이저는 다른 ID로 추가해도 기능 속성과 호환 설정을 갖추면 동일한 레이저 동작을 사용한다. 색상·거리·강도별 변형 설정은 이번 변경에 포함하지 않는다. 기능 속성은 아이템 정의에서 읽으므로 세이브 필드를 추가하지 않는다.
