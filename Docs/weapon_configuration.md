# 무기 스펙·외형과 적 지급 장비

아래 파일은 `TunaSweeper/Content/Data`에 있으며 아이템 데이터 로딩 시 함께 읽는다. 아이템 ID는 참조값이고, C++에서 특정 번호를 무기 종류로 판정하지 않는다. 기존 세이브 형식은 변경하지 않는다.

## 총기 스펙: WeaponDefinitions.json

`ItemTable.json`에는 이름·설명 키, 가격, 등급, 아이콘, 카테고리, 장비 슬롯 등 아이템 공통 정보를 둔다. 총기 스펙은 `WeaponDefinitions.json`에서 `item_id`로 연결한다.

| 필드 | 의미 |
|---|---|
| `item_id` | ItemTable에 존재하는 총기 ID. 총기마다 정확히 한 행 필수 |
| `weapon_type_tag` | 총종 태그. 예: `weapon.type.rifle` |
| `fire_mode` | `semi_automatic` 또는 `automatic` |
| `compatible_ammo_type_tags` | 사용할 수 있는 탄종 태그. 대응 탄약 아이템이 있어야 함 |
| `magazine_capacity` | 기본 탄창 용량. 1 이상의 정수 |
| `reload_seconds` | 기본 재장전 시간(초). 0보다 큰 유한한 값 |
| `attachment_slot_tags` | 지원하는 부착 슬롯 목록. 부착물을 지원하지 않으면 빈 배열 |

현재 총기 1001·1002·1003·1006·1007·1008의 기존 수치를 그대로 이전했다. 근접무기 외형은 기존 외형 파일에서 관리하며, 탄약과 부착물의 속성은 해당 아이템 정의에 둔다. 확장 탄창의 `magazine_capacity_bonus`도 부착물 아이템 속성이다.

로더는 ItemTable 다음에 총기 스펙을 읽어 런타임 `FTunaSweeperItemDefinition`에 결합하고, 그 뒤 외형·적 지급 설정을 검증한다. 플레이어와 적은 같은 결합된 정의를 사용한다. 위 스펙 필드를 ItemTable에 다시 쓰면 오류로 처리한다. 누락·중복·비총기/없는 ID·잘못된 수치는 전체 로딩 실패이며, 검증에 실패한 스펙으로 일부 무기만 갱신하지 않는다.

CSV 뷰어의 `item_definitions.csv`는 두 JSON을 결합한 조회용 표다. 무기 스펙 편집 원본은 `WeaponDefinitions.json`이며 CSV 재생성도 이 파일을 읽는다.

## 무기 외형: WeaponVisualDefinitions.json

아이템별 메시와 재질, 부착 위치를 정의한다. 플레이어의 총기·근접무기와 적 총기에 같은 적용 함수를 사용한다. 행이 없는 무기는 원래 무기 액터의 외형을 사용한다. 총기 액터 클래스 선택은 기존 `WeaponActorClassMappings.json`이 담당한다.

| 필드 | 의미 |
|---|---|
| `item_id` | ItemTable에 존재하는 총기 또는 근접무기 ID |
| `mesh`, `material` | UE 메시·재질 오브젝트 경로 |
| `location` | 무기 액터 기준 상대 위치 `[X,Y,Z]`, cm |
| `rotation` | 상대 회전 `[Pitch,Yaw,Roll]`, 도 |
| `scale` | 양수인 축별 배율 `[X,Y,Z]` |
| `align_longest_axis_to_x` | 원본 메시에서 가장 긴 축을 X축으로 정렬 |
| `center_on_bounds` | 메시 경계 상자의 중심을 기준으로 위치 보정 |
| `fit_length_cm` | 0이면 크기 맞춤 생략. 양수이면 배율 적용 후 가장 긴 축의 길이를 지정값으로 맞춤 |

모든 필드를 명시한다. 정렬 후 추가 회전을 적용하고, 크기를 맞춘 뒤 중심 보정을 적용한다. 기존 방망이 두 종은 같은 야구방망이 메시를 유지하며, 쇠지렛대는 기존 70cm 크기와 중심 정렬을 유지한다.

JSON 경로만으로 새 에셋이 자동으로 쿠킹되는 것은 아니다. 새 메시·재질은 기존 쿠킹 대상 폴더 또는 에셋 참조에 포함해야 한다.

## 적 기본 무장: EnemyDefaultLoadout.json

- `weapon_item_id`: 스폰 무기가 미지정되거나 유효한 총기가 아니면 사용할 기본 무기.
- `reserve_magazine_count`: 예비 탄수가 미지정이면 적용할 탄창 수. 탄창 용량 × 이 값으로 예비 탄수를 구한다.
- `ammo_by_weapon_type`: 무기 종류 태그와 기본 탄약 ID 목록. 명시된 탄약이 없거나 무기와 맞지 않을 때 사용한다.

스폰에 명시한 유효한 무기·호환 탄약·예비 탄수를 우선한다. 기본 탄약 목록에 없는 무기 종류에는 소총탄을 임의로 지급하지 않는다. 해당 종류의 총기와 기본 탄약이 호환되어야 하며, 중복 태그·알 수 없는 태그·음수·정수가 아닌 수량·계산 범위 초과는 오류다.

현재 기본 무기는 1002, 예비 탄창은 2개다. 권총·기관단총은 2001, 소총은 2002, 산탄총은 2003을 사용한다.

## 실험실 적 지급: CombatLabEnemyLoadout.json

`weapon_item_id`, `ammo_item_id`, `reserve_ammo_count`로 실험실 적 3명의 공통 지급 장비를 정한다. 일반 적 기본 무장과 별도로 읽고 검증하며, 현재는 1002·2002·예비 120발이다. 잘못된 설정이면 기존 오류 문자열 키로 라운드 시작을 중단한다.

## 오류와 재로딩

설정 파일의 누락, 파싱 오류, 존재하지 않는 아이템, 중복 외형 행, 잘못된 수치, 부적합한 무기·탄약 조합은 경로를 포함한 오류 로그를 남기고 아이템 데이터 로딩을 실패시킨다. 검증 도중 부분적으로 읽힌 설정은 사용하지 않는다. 메시·재질은 실제 적용 시 로딩하며 실패하면 오류를 기록한다.

에디터/게임을 재시작하거나 기존 `LoadItemData(true)` 강제 재로딩 경로를 사용한다. 이미 생성된 액터를 자동으로 다시 장착시키는 실시간 갱신 기능은 없다.

## 월드 진행 요구 재료

`RequiredItemId`의 기본값은 미지정(`INDEX_NONE`)이다. 설정 함수에 0 이하의 값을 넘기거나, 그런 상태로 플레이가 시작되면 오류 로그를 남긴다. 재료 투입·수리·즉시 수리 완료와 상호작용을 차단하며 목재 ID로 대체하지 않는다.

기존 `BP_WorldProgress_BrokenBridge`에는 목재 6002를 명시한다. 새로운 월드 진행 액터도 에셋 또는 설정 데이터에서 요구 재료를 직접 지정해야 한다.

## 검증

자동화 테스트 `TunaSweeper.Data.WeaponConfiguration`은 미지정 재료 차단, 기존 다리 설정, 실제 메시 적용, 새 ID 외형 조회, 기본/명시적/실험실 무장 선택, 잘못된 데이터 거부와 기존 설정 보존을 검사한다.
