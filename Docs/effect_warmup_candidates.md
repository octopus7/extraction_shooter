# 전투 이펙트 웜업 후보 수집

현재 단계는 실제 플레이에서 요청한 에셋 경로 수집이다. 사전 로딩, Niagara 실행,
PSO 컴파일 대기, 히치 시간 측정은 수행하지 않는다. 기본값은 수집 꺼짐이다.

## 사용

1. PIE 또는 개발 빌드의 게임 콘솔에서 `tuna.FX.CollectCandidates 1`을 실행한다.
2. 총기 발사, 여러 표면 피격, 수류탄 및 폭발통 폭발을 재현한다.
3. `tuna.FX.DumpCandidates`로 JSON을 내보낸다.
4. `tuna.FX.CollectCandidates 0`으로 수집을 멈춘다.

결과는 프로젝트 `Saved/EffectWarmup/Candidates-*.json`에 저장되고 출력 로그에
절대 경로가 표시된다. 수집 결과가 있으면 정상적인 게임 인스턴스 종료(PIE 종료 포함)에도
자동 저장한다. 강제 종료 시에는 자동 저장을 보장하지 않는다. 내보내기는 동기 파일 쓰기이므로
성능 측정 중에는 실행하지 않는다. 매번 별도 파일을 만들며 이전 결과와 자동 병합하지 않는다.

`tuna.FX.ResetCandidates`는 현재 게임 인스턴스의 메모리 목록만 비운다.
맵 이동에서는 목록을 유지하고, 서로 다른 게임 인스턴스/PIE 클라이언트는 분리한다.
수집 설정은 프로세스 공통이며 수집을 꺼도 기존 목록은 유지한다.
시작부터 수집하려면 개발 실행 인자 `-ExecCmds="tuna.FX.CollectCandidates 1"`을 사용한다.

## 수집 범위와 해석

- 총구 Niagara, 총기 프레젠테이션 데이터와 발사음.
- 피격 프로필, 선택된 Niagara·사운드·허용된 데칼, 기존 피격 효과 클래스·재질.
- 투사체 본체·궤적에 전달된 재질. 동적 재질은 저장 가능한 부모 재질로 기록한다.
- 로컬 폭발 Niagara·왜곡 재질, 폭발통의 폭발 클래스·사운드.
- 수류탄이 선택한 Niagara 또는 Cascade 효과와 폭발음.

각 항목에 `assetPath`, `requestCount`, 중복 제거한 `sources`를 기록한다.
요청 경로를 로딩 전에 기록하므로 존재하지 않거나 로딩에 실패한 경로도 포함될 수 있다.
사용 횟수는 계측 지점의 요청 횟수이며 렌더 횟수나 프리징 횟수가 아니다.
빈 경로, 임시 객체, 하위 객체는 제외한다. 에셋의 의존 관계는 재귀 탐색하지 않는다.
플레이하지 않은 효과, 계측하지 않은 BP 전용 스폰 경로, 적 사망·연소·환경 연기 등은
이 목록만으로 전부 수집되지 않는다. 이후 웜업 구현에서 경로 유효성·의존 에셋·PSO 준비를
별도로 처리해야 하며 JSON 생성만으로 쿠킹 대상에 추가되지는 않는다.
