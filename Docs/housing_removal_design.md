# 하우징 시스템 완전 제거 설계

> 상태: 구현 승인됨. 기존의 `UTunaSweeperHousingSubsystem::ShouldCreateSubsystem()` 최소 비활성화를 포함해 아래 범위를 완전히 제거한다.

## 목표

더 이상 사용하지 않는 벙커 하우징 배치 시스템을 런타임, UI, 입력, 저장, 퀘스트 데이터에서 완전히 제거한다. 시설별 액터 언락 시스템은 이번 변경에 포함하지 않고 후속 작업으로 남긴다.

## 제거 범위

- `UTunaSweeperHousingSubsystem`과 하우징 배치 정의·상태 타입
- 하우징 영역, 격자 시각화, 배치 프리뷰, 배치 시설 및 NPC 시설 래퍼 액터
- 벙커 시설관리 상호작용 액터와 `HousingManagement` 상호작용 타입·처리 분기
- 하우징 패널, 시설 컨텍스트 메뉴, HUD 표시 및 갱신 경로
- 플레이어 컨트롤러의 하우징 카메라, 이동·회전·확정·취소 입력과 모드 전환 경로
- 캐릭터·상호작용 시스템·일시정지 메뉴 등에 있는 하우징 모드 억제 조건
- `HousingFacilityDefinitions.json`과 전용 UI 문자열
- 세이브의 배치 시설 목록 및 하우징 시설 해금 목록
- 퀘스트 보상의 하우징 시설 해금 필드와 로드·표시·지급 경로

## 보존 범위

- 창고, 상점, 작업대, 돼지저금통 등 레벨에 독립적으로 배치되어 자체 기능을 제공하는 시설 액터
- 일반 월드 진행 저장 상태와 기존 시설 액터의 고유 저장 데이터
- 향후 시설별 액터 언락 구현에 재사용할 수 있는 일반 상호작용·월드 진행 기반 구조

## 데이터 및 이전 세이브 처리

하우징 전용 저장 필드는 코드에서 제거한다. 이전 세이브에 남은 직렬화 데이터는 더 이상 읽거나 쓰지 않으며, 다른 저장 필드는 기존대로 로드한다. 하우징 언락 데이터를 새 시설별 언락 데이터로 변환하는 마이그레이션은 만들지 않는다.

공개 퀘스트 데이터에 남은 `housing_facilities` 또는 `housing_facility_unlocks` 보상은 제거한다. 이는 후속 시설별 액터 언락 작업에서 새 보상 형식으로 다시 정의한다.

## 런타임 결과

벙커 맵 로드 시 하우징 영역이나 시설관리 액터가 자동 생성되지 않는다. 시설관리 상호작용, 하우징 UI, 배치 모드 및 전용 카메라·입력은 존재하지 않는다. 독립 시설 액터는 현재 레벨 배치와 자체 상호작용 규칙에 따라 계속 동작한다.

## 문서 정리

현재 동작을 설명하는 하우징 전용 문서는 제거하거나 폐기 상태로 갱신한다. 시스템 흐름, 저장 영속성 및 게임 규칙 문서에서 하우징을 현재 기능으로 설명하는 내용을 삭제한다. 과거 요청·질문 로그는 이력 보존을 위해 수정하지 않는다.

## 검증

1. 소스·설정·콘텐츠 데이터에서 활성 하우징 심볼과 파일 참조가 남지 않았는지 정적 검색한다.
2. Quest Studio의 Demo 데이터 상태를 확인하고 필요한 경우 pull한 뒤 데이터를 수정하며, 수정 후 Demo 퀘스트 검증을 실행한다. 명시적 요청이 없으므로 push하지 않는다.
3. UE 5.7 Development Editor 타깃을 빌드한다.
4. 빌드 성공 후 `TunaSweeper.uproject`를 명시해 에디터를 연다.
5. 작업 기록과 앞선 질문 기록을 포함해 하나의 최종 커밋으로 만든다.

## 비목표

- 시설별 액터 언락 시스템 설계 또는 구현
- 기존 하우징 해금 상태의 신규 시스템 마이그레이션
- 독립 시설 액터의 레벨 배치나 외형 변경
- 퀘스트 데이터 배포 또는 원격 게시
