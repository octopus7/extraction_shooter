# 게임 기준

이 문서는 TunaSweeper에서 공통으로 사용하는 방향, 거리, 단위, 재화 같은 게임 기준을 기록한다.

## 방향 기준

- 월드 기준 북쪽은 `+X` 축이다.
- 화면 기준 12시 방향은 북쪽으로 본다.
- 따라서 화면 기준 12시 방향으로 이동하거나 배치한다고 말하면 월드 좌표에서는 `+X` 방향을 의미한다.
- `+Y` 축은 북쪽 기준 오른쪽 방향으로 본다.
- `+Z` 축은 위쪽 방향이다.
- 적의 시선·몸체 yaw 회전은 전투 프로필의 `turn_speed_degrees_per_second`를 초당 각도 상한으로 사용한다. 목표가 크게 바뀌어도 즉시 회전하거나 각도 차이에 비례해 가속하지 않는다.
- 적의 원거리 발사와 근접 타격은 `attack_facing_tolerance_degrees` 안으로 정렬된 뒤에만 허용하며 공격 함수가 캐릭터 회전을 스냅해서는 안 된다.

## 거리 기준

- Unreal Engine 기본 단위는 cm이다.
- 게임 내 `1m`는 Unreal 월드 좌표 `100` 단위로 본다.
- 예: 중심에서 북쪽으로 `7m`는 중심 기준 `+X 700` 위치를 의미한다.
- 일반 총기 적은 별도 공격 거리 제한을 사용하지 않는다. 교전 중 사격 여부는 직접 시야·사선, 조준각, 탄약, 전투 FSM으로 결정하고 이동 거리는 `preferred_range_min/max`와 `danger_range`로 결정한다.
- 적 근접 공격 거리는 프로필 데이터가 아니라 `TunaSweeperEnemyCombatConstants::MeleeAttackRange` 전역 상수 하나로 관리한다.

## 이동 발소리 기준

- 플레이어 발소리는 애니메이션 노티에 의존하지 않고 실제 수평 이동 속도와 이동 모드로 발생시킨다.
- 지상에서 80cm/s 이상 이동할 때만 발소리를 내며 정지·공중·구르기 중에는 발생시키지 않는다.
- 걷기와 질주는 각각 독립된 간격 범위를 사용하고 매 발소리 뒤 다음 간격을 다시 무작위로 선택한다.
- 실제 오디오와 AI 청각 소음 이벤트는 분리한다. 오디오 애셋이 없어도 `noise.player_footstep`은 보고한다. 플레이어 발소리 오디오는 게임 인스턴스가 참조하는 `DA_PlayerFootstepPresentation`의 `BasicFootstepSound`에서 가져오며, 재질별 사운드는 향후 전용 리졸버에서 선택한다.
- 플레이어 발소리는 플레이어를 source/instigator로 보고해 팩션 관계 판정을 거친다. 적대 AI는 듣고 같은 팩션 AI는 무시한다.

## 아이템 아이콘 기준

- 게임에서 사용하는 개별 아이템 아이콘 파일은 `256x256` 크기를 기준으로 한다.
- 4x4 아이템 아이콘 시트는 `1024x1024` 크기를 기준으로 하며, 각 칸은 `256x256`이다.
- 고해상도 작업 원본을 별도로 만들더라도 최종 게임용 개별 아이콘은 `256x256`으로 맞춘다.

## 시간 연출 기준

- 기본 페이드 연출 단위는 약 `0.2초`로 짧게 잡는다.
- 특별히 느린 전환이 필요한 경우가 아니면 UI/화면 전환 페이드는 `0.2초`를 기준으로 한다.

## 재화 기준

- 기본 재화는 코인이다.
- 코인은 저장 데이터의 기존 필드명 `QuestCoinBalance`에 저장하지만, UI와 문서에서는 일반 재화로 취급한다.
- 재화 UI는 흰색 단색 코인 아이콘과 숫자를 함께 표기한다.
- 인게임 재화 UI에는 `$` 표기를 사용하지 않는다.
- 부품 조각은 제작/수리 재료이며 재화로 표기하지 않는다.
- 옛 문명의 동전과 지폐는 인벤토리 아이템이며 재화가 아니다. 저금통 저금 상호작용에서만 지폐 1장을 옛 문명 동전 10개 가치로 환산한다.

## 무기 확산/리코일 기준

- 총기 확산과 리코일 상수는 개별 무기가 아니라 총종 태그 기준으로 관리한다.
- `DA_WeaponSpreadRecoil`의 최소/최대 확산 값은 조준 중심에서 좌우로 벌어지는 반각 degree 단위로 본다.
- 플레이어 조준 사격은 `AimedSpreadMultiplier`만 적용한 기존 반각을 유지하고, 힙파이어는 현재 비조준 반각에 `5.0`을 곱한다.
- 적 원거리 사격은 현재 무기 반각에 `EnemyCombatProfiles.json`의 `weapon_spread_multiplier`를 곱한다. 역할별 정확도 차이는 이 프로필 값으로 조정한다.
- 화면 리코일은 실제 커서 좌표를 바꾸지 않고, 리코일 벡터를 화면 픽셀 오프셋으로 환산해 크로스헤어와 발사 기준점에만 적용한다.
- 리코일 벡터가 `0`이어도 실제 발사 탄도에는 총종별 최소 확산이 적용된다.

## 전투 수치 기준

- 탄약 피해 보너스와 방어구 방어 수치는 정수 1단위로 관리한다.
- 탄약 최종 피해는 `round(기본 투사체 피해 x 탄약 피해 배율) + 탄약 피해 보너스`를 0 이상 정수로 보정해 적용한다.
- 플레이어가 받는 피해는 장착 중인 장비의 방어 수치 합계를 뺀 뒤 `max(0, 들어온 피해 - 방어)`로 적용한다.
- 공격과 방어는 현재 장비/탄약 데이터로만 보정하며, 레벨 기반 공격력 또는 방어력 증가는 적용하지 않는다.
- 피해량 숫자는 실제 체력/내구도 처리를 가진 대상에게 적용된 피해만 표시하고, 벽처럼 체력 없는 충돌 오브젝트에는 표시하지 않는다.

## 아슬아슬한 회피와 스크래치 기준

- 스크래치는 현재 세이브에 기록하지 않는 플레이어 런타임 자원이며 범위는 `0~100`이다. 향후 소비 용도와 초기화 정책이 확정될 때 저장 여부를 다시 결정한다.
- 적대 공격이 플레이어의 구르기 중 위험 영역을 통과했을 때만 Near Miss로 인정한다. 공격 하나는 같은 플레이어에게 한 번만 스크래치를 지급한다.
- 투사체 Near Miss는 프레임별 점 위치가 아니라 투사체의 이전·현재 위치 선분과 플레이어 캡슐 사이의 최소 간격으로 판정한다.
- 투사체 표면과 플레이어 캡슐 표면 사이 간격이 `40cm` 이하면 Graze, 원래 충돌 영역이 겹치면 Perfect Dodge로 본다.
- 기본 획득량은 투사체 `8`, 근접 `12`이며 Perfect Dodge는 해당 획득량의 `1.5배`다.
- Near Miss 슬로모션의 시작과 복구는 전역 시간 배율의 영향을 받지 않는 실시간을 사용하고, 플레이어의 유효 시간 배율을 별도로 보정해 구르기 무적 시간이 과도하게 늘지 않게 한다.

## 전투 팩션 기준

- `FactionId`는 `1~254`를 사용하고 `255`는 `NoFaction`으로 예약한다.
- 현재 기본 팀은 플레이어·펫 `1`, 일반 적·롤링 봄버·롤링 봄버 스포너 `10`이다.
- 같은 유효 ID는 Friendly, 다른 유효 ID는 Hostile, 미지정 ID는 Neutral로 판정한다.
- 전투 코드에서는 ID를 직접 비교하지 않고 `UTunaSweeperFactionSubsystem`의 관계 판정기를 사용한다.
- 팩션 없는 폭발통 등 환경 피해원은 기존 환경 피해를 유지한다.
- 2인 전술 분대의 키는 `(FactionId, SquadId)`이며 같은 팩션이라도 다른 `SquadId`는 역할 lease와 접촉 정보를 공유하지 않는다.
- 정적 팩션·분대 배정과 런타임 전투 lease는 저장 대상이 아니다. 향후 동맹 관계를 영속화할 때만 세이브 버전을 갱신한다.

## 아이템 슬롯 UI 기준

- 아이템 슬롯 그리드 UI는 한 줄 5칸을 SSOT 규칙으로 사용한다.
- 데이터 용량, 상자 용량, 창고 용량, 상점/작업대 목록 개수는 5의 배수로 강제하지 않는다.
- UI는 실제 슬롯/목록 개수를 5칸 단위로 올림해 줄을 구성하고, 남는 칸은 표시용 패딩 칸으로 둔다.
- 점유 수와 용량 표기는 표시용 패딩 칸을 제외하고 실제 데이터 기준으로 계산한다.
- 아이템 등급 슬롯 표시는 아이콘 뒤 수직 그라데이션을 기본으로 사용하고, 상단 accent 띠는 Rare 이상 등급에만 적용한다.
- 등급 색상 흐름은 Common 회색, Uncommon 초록, Rare 청색, Epic 보라, Legendary 금색을 기준으로 한다.
