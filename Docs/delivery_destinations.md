# 배달 완료 상호작용

`/Game/Interaction/Parcels/BP_DeliveryDestination`을 목적지에 배치한다. 부모 클래스는 `ATunaSweeperDeliveryDestinationActor`다. 기본값은 특정 퀘스트를 지정하지 않으며 아래 세 항목을 설정해야 활성화된다. 상자에서 아이템을 가져오는 기능은 [택배 상자](parcel_containers.md)를 참고한다.

## 설정

- `QuestId`: 배달 퀘스트의 정수 ID.
- `ObjectiveId`: 해당 퀘스트의 제출 목표 `objective_id`.
- `DestinationId`: 목표의 `target_provider_id`와 일치하는 목적지 식별자.

목표는 기존 `item_submitted` 형식을 사용한다. `item_id`와 `required_count`는 퀘스트 정의에서만 관리한다. `target_provider_id`는 제출 대상을 나타내며, 목적지에는 `delivery.*`처럼 NPC 제공자와 구분되는 ID를 사용한다. 퀘스트의 제공자·보상 수령 NPC 설정은 변경하지 않는다.

## 동작

- 지정 퀘스트가 진행 중이고 해당 목표에 필요한 아이템을 보유했을 때 `배달하기` 상호작용을 표시한다. 인벤토리 변경과 퀘스트 저장 복원 시 즉시 갱신한다.
- 같은 월드의 플레이어가 상호작용 거리 안에서 실행해야 한다. 목적지 ID·퀘스트 ID·목표 ID가 일치하지 않으면 소비하지 않는다.
- 필요한 남은 수량을 한 번에 소모하고 그 목표를 달성한다. 다른 목표가 남아 있으면 퀘스트는 계속 진행 중이다. 모든 목표가 끝나면 보상 수령 가능 상태로 바뀌며 보상은 자동 지급하지 않는다.
- 소모와 목표 변경을 완료한 뒤 인벤토리 알림·저장을 수행한다. 재진입, 재상호작용, 저장 복원으로 같은 목표에 다시 제출하지 않는다.
- 목적지 액터의 자체 완료 플래그 대신 기존 퀘스트 진행 저장을 사용한다. 목적지에 장식용 메시를 붙일 수 있으며 메시 유무는 판정에 영향을 주지 않는다.

실제 맵 위치와 액터 배치는 레벨 저작 작업에서 지정한다. 배달 아이템의 기지 귀환 시 소멸은 별도 수명 처리다.
