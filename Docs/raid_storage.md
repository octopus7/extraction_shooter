# 레이드 영구 보관함

## 배치와 교체

- 실제 애셋: `/Game/Interactables/RaidStorage/BP_RaidStorage`.
- 부모 클래스: `ATunaSweeperRaidStorageActor`. 기존 전리품 상자의 열기 UI와 뚜껑 애니메이션을 재사용한다.
- 기본 용량은 10칸이며 일반 창고와 별개다. 같은 세이브 슬롯에서 모든 인스턴스는 같은 내용물을 사용한다.
- 의도된 배치는 하나다. 중복 배치가 발견되면 열 때 화면 디버그 경고를 표시한다. 중복 액터를 강제로 삭제하거나 별도 창고로 분기하지 않는다. 경고는 현재 로드된 월드의 인스턴스를 기준으로 한다.
- 이번 작업은 배치용 BP를 제공하며, 지정되지 않은 게임 맵에는 임의로 배치하지 않는다.

BP의 `VisualMesh`, `LidMesh` 및 철제 보강재·손잡이 컴포넌트는 교체 가능한 임시 외형이다. 뚜껑은 `LidPivot`과 기존 애니메이션 설정을 사용한다. 본체와 뚜껑 메시를 교체할 때 크기·충돌·힌지 위치를 함께 조절한다. `bUseComponentMeshPresentation`을 유지하면 전리품 테이블의 외형으로 덮어쓰지 않는다.

## LED

전면(+X)에 가로 5개, 세로 2개를 배치한다. 슬롯 0~4가 윗줄, 5~9가 아랫줄이다. 앞에서 바라봤을 때 왼쪽부터 슬롯 순서대로 대응한다.

| 내용물 | 표시 |
| --- | --- |
| 빈칸 | 꺼짐 |
| 일반 참치 통조림(3004) 1~9개 | 어두운 녹색 |
| 일반 참치 통조림(3004) 10개 | 밝은 녹색 |
| 다른 아이템(미식 참치 포함) | 주황색 |

`M_RaidStorageLED`의 `IndicatorColor` 파라미터를 갱신하는 이미시브 표현이다. 라이트 컴포넌트는 없다. `FullTunaColor`, `PartialTunaBrightness`(기본 0.5), `OtherItemColor`를 BP 기본값에서 조절할 수 있다. 0.5는 선형 이미시브 배율이며 노출·톤매핑 후 체감 밝기는 달라질 수 있다.

LED 메시를 교체할 때 `RaidStorageLED_0`부터 `RaidStorageLED_9`까지의 컴포넌트 태그를 각각 하나씩 유지하고, `IndicatorColor`를 가진 머티리얼을 지정한다. 태그가 슬롯과 표시를 연결하므로 컴포넌트 이름이나 메시 자체는 바꿔도 된다.

## 저장

`UTunaSweeperSaveGame.RaidStorageSlots`와 기존 아이템 인스턴스 목록에 함께 기록한다. 넣기·꺼내기·병합·분할·사용·제거 등 변경 후 즉시 동일한 세이브 파일에 저장을 시도한다. 창을 닫을 때까지 기다리지 않는다. 저장 실패 시 현재 상태를 메모리에 유지하고 경고하며, 다음 변경이나 닫기에서 다시 저장을 시도한다.

지역 이동·사망·레이드 포기로 소지품이 초기화되어도 보관함은 남는다. 다른 세이브 슬롯과 새 게임은 독립적이다. 기존 세이브에는 새 필드가 없으므로 빈 10칸으로 시작한다. 이 창고에서 꺼내는 행위는 새 전리품 획득이 아니므로 획득 경험치·획득 퀘스트 이벤트를 반복 지급하지 않는다. 기지의 제작·제출용 원격 재료 목록에 이 보관함을 추가하지 않는다.

화면 이름과 경고는 `UITextStrings.csv`의 `ui.raid_storage.*` 키를 사용한다.

## 검증

자동화 그룹: `TunaSweeper.RaidStorage`. 디스크 검증은 `-UserDir=<프로젝트>/Saved/RaidStorageAutomation/`을 사용해 사용자 세이브와 분리한다. 별도 경로가 없으면 디스크 검증을 건너뛰고 경고한다. 테스트는 저장 필드, 즉시 디스크 기록, 공유 인스턴스, 꺼내기·분할의 경험치 억제, 사망 보존, 재로드, 저장 실패 재시도, 슬롯 전환 초기화, 실제 BP의 LED 10개와 라이트 부재를 확인한다.
