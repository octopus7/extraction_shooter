# 데이터 작성 기준

이 문서는 TunaSweeper의 JSON/테이블 원본 데이터 작성 규칙을 정리하는 SSOT 문서다.

## 확률/비율

- 데이터 원본의 모든 게임플레이 확률, 배율, 비율 값은 `10000`분율 정수로 기록한다.
- `10000`은 100%, `1000`은 10%, `100`은 1%, `1`은 0.01%다.
- 원본 데이터 필드 타입은 정수여야 하며, `0.3`, `0.04`, `30%` 같은 float/문자열 표기는 사용하지 않는다.
- 확률 값은 `0`부터 `10000`까지 사용한다.
- 배율/비율 값은 `10000`을 1.0배 기준으로 사용하며, 1.0배를 넘는 값은 `10000`보다 크게 기록할 수 있다.
- UI 표시는 필요하면 런타임에서 변환해 소수점 퍼센트 또는 소수점 배율로 보여줄 수 있다.
- 확률/비율 데이터 필드명에는 분모를 적지 않는다. 별도 언급이 없는 모든 확률/비율 필드는 이 문서의 10000분율 정수 규칙을 따른다.

예:

```json
{
  "base_apply_chance": 400,
  "bleed_chance_bonus": 3000,
  "projectile_damage_multiplier": 10000,
  "headshot_damage_multiplier": 60000
}
```

## 중량 디버프 기준
- 중량 과다와 이동불가 기준은 `TunaSweeper/Content/Data/DebuffDefinitions.json`의 `carry_weight` 전역 설정을 SSOT로 사용한다.
- `overweight_threshold`는 중량 과다 기준과 인벤토리 중량 게이지의 삼각형 기준 위치를 함께 제어한다. 기본값은 `7000`이며 70%를 뜻한다.
- `movement_blocked_threshold`는 이동불가 전환 기준이다. 기본값은 `10000`이며 100%를 뜻한다.
- `overweight_speed_multiplier`는 중량 과다 상태의 이동속도 배율이다. 기본값은 `5000`이며 50%를 뜻한다.
- 위 필드는 모두 프로젝트 공통 규칙에 따라 10000분율 정수 원본값으로 기록한다.
- `carry_strength_increase`와 `carry_strength_bonus`는 비율이 아니라 근력 원본 수치다. 레벨 보상 테이블과 아이템 테이블에 실제 근력 증가량으로 기록한다.
- 중량 과다와 이동불가는 지속시간이 없는 조건형 디버프이며, 조건을 만족하면 즉시 적용되고 해소되면 즉시 제거된다.
- 이동불가 조건을 만족하면 중량 과다 디버프를 대체하며, WASD 이동은 막고 구르기 이동은 허용한다.

위 값은 각각 4%, 30%, 1.0배, 6.0배를 뜻한다.

## 디버프 재적용

- 같은 디버프 ID가 이미 활성 상태인 대상에게 다시 적용되면, 새 적용값으로 기존 상태를 덮어쓴다.
- 동일 ID 디버프는 누적 스택을 만들지 않고, 기존 값과 새 값의 강도를 비교해 더 높은 효과일 때만 갱신하지도 않는다.
- 새로 덮어쓴 값이 기존보다 낮아 플레이어에게 이득이 되는 경우는 설계상 고려하지 않는다.

## 제외 디버프

- 중독은 게임에서 사용하지 않는다.
- 중독 디버프, 독 피해, 해독제 중심의 대응 루프는 데이터/아이템/적 패턴에 추가하지 않는다.
