# 작업대 조제법 설계와 설계도 해금 기준

이 문서는 TunaSweeper 작업대의 조제법 설계, 설계도 아이템, 해금 방식의 SSOT 문서다.

## 핵심 기준

- 조제법 설계와 설계도 아이템은 별개의 개념이다.
- 조제법 설계는 실제 제조 규칙이고, 설계도 아이템은 그 조제법을 해금하기 위한 선택적 전달 수단이다.
- 모든 조제법 설계가 설계도 아이템을 가져야 하는 것은 아니다.
- 설계도 아이템 없이 존재하는 조제법 설계가 정상 구조다.
- 조제법 해금 여부는 `recipe_id`를 기준으로 판단한다.
- 표시명, 아이템 이름, 설계도 아이템 이름은 해금 키로 쓰지 않는다.

## 용어

- 조제법 설계: `Content/Data/WorkbenchRecipes.json`에 들어가는 실제 제조 데이터다. `recipe_id`, `workbench_id`, 결과 아이템, 재료, 기본 해금 여부를 가진다.
- 설계도 아이템: 인벤토리나 창고에 들어갈 수 있는 일반 아이템이다. 필요할 때만 `Content/Data/ItemTable.json`에서 `blueprint_recipe_id`로 조제법 설계를 가리킨다.
- 설계도 등록: 설계도 아이템 1개를 소비해서 그 아이템이 가리키는 `recipe_id`를 해금하는 작업대 동작이다.
- 해금 상태: 저장 슬롯별로 열린 조제법 목록이다. 기본 제공 조제법은 저장 목록에 쓰지 않아도 항상 열린다.

## 데이터 소유

- 제조 조제법 설계 원본은 `Content/Data/WorkbenchRecipes.json`이다.
- 분해 결과 원본은 `Content/Data/WorkbenchDismantleRecipes.json`이다.
- 설계도 아이템 원본은 `Content/Data/ItemTable.json`이다.
- 퀘스트 보상 해금 원본은 `Content/Data/QuestDefinitions.json`의 보상 필드다.
- 저장되는 해금 상태는 `UTunaSweeperSaveGame::UnlockedWorkbenchRecipeIds`다.

## 조제법 설계 규칙

- `recipe_id`는 안정적인 영구 키로 본다.
- `recipe_id`는 저장 데이터, 퀘스트 보상, 설계도 아이템 참조에 쓰이므로 한 번 배포한 뒤에는 바꾸지 않는다.
- `output_item_id`와 `ingredients[].item_id`는 실제 아이템 ID를 참조해야 한다.
- 기본 제공 조제법은 `auto_unlocked: true`로 둔다.
- 퀘스트나 설계도 등록으로 열 조제법은 `auto_unlocked`를 false 또는 생략 상태로 둔다.

## 설계도 아이템 규칙

- 설계도 아이템은 조제법 설계를 담고 있는 원본 데이터가 아니다.
- 설계도 아이템은 조제법 설계를 해금시키는 티켓에 가깝다.
- 설계도 아이템이 사라져도 이미 해금된 조제법은 유지된다.
- 설계도 아이템은 `blueprint_recipe_id`로 하나의 `recipe_id`를 가리킨다.
- 여러 설계도 아이템이 같은 `recipe_id`를 가리킬 수는 있지만, 이미 해금된 조제법은 중복 등록되지 않는다.
- 설계도 등록 UI 후보는 설계도 분류 아이템이거나 `blueprint_recipe_id`가 있는 아이템이다.

## 해금 방식

### 기본 제공

- `WorkbenchRecipes.json`에서 `auto_unlocked: true`로 설정한다.
- 설계도 아이템이 필요 없다.
- 퀘스트 보상도 필요 없다.
- 저장 데이터에 별도로 기록하지 않아도 항상 표시된다.
- 예: `recipe.large_water_bottle`은 생수 2개로 큰생수를 만드는 기본 제공 조제법이다.

### 퀘스트 보상

- 퀘스트 보상에 `workbench_recipes` 또는 `workbench_recipe_unlocks`로 `recipe_id`를 넣는다.
- 보상 수령 시 해당 조제법을 해금한다.
- 해금된 `recipe_id`는 저장 데이터에 기록한다.
- 퀘스트 보상으로 열리는 조제법은 보통 `auto_unlocked`를 켜지 않는다.

### 설계도 등록

- 아이템 정의에 `blueprint_recipe_id`를 설정한다.
- 플레이어가 해당 아이템을 인벤토리나 창고에 보유하면 작업대 설계도 등록 UI에 후보로 표시된다.
- 등록 가능한 상태에서 등록하면 설계도 아이템 1개를 소비하고 `recipe_id`를 해금한다.
- 해금된 `recipe_id`는 저장 데이터에 기록한다.
- 이미 해금된 조제법을 다시 등록하지 않는다.
- 예: `recipe.king_water_bottle`은 `설계도 왕생수` 아이템 등록으로만 열리는 조제법이다. 재료는 생수 1개와 큰생수 1개이고, 출력은 왕생수 1개다.

## 분해와의 관계

- 분해 데이터는 제조 조제법 해금과 별개다.
- 현재 분해는 `WorkbenchDismantleRecipes.json`에 정의된 원본 아이템과 결과 목록을 기준으로 한다.
- 분해 가능 여부는 조제법 설계도 해금 상태가 아니라, 대상 아이템과 분해 데이터 존재 여부로 판단한다.
- 왕생수는 설계도 해금으로 제조하지만, 분해는 해금 여부와 무관하게 왕생수 1개를 생수 2개로 돌린다.
- 분해 데이터에도 해금 단계가 필요해지면 별도 SSOT 기준을 추가한다.

## 추가 기준

- 기본 제공 조제법을 만들 때는 설계도 아이템을 임의로 만들지 않는다.
- 설계도 등록용 아이템이 필요한 경우에만 아이템 데이터를 추가한다.
- 조제법 이름을 바꿔야 하면 문자열 키나 표시명만 바꾸고 `recipe_id`는 유지한다.
- 출력 아이템이나 재료 아이템이 없으면 먼저 아이템 데이터를 추가한다.
- 아이템 보유 여부만으로 조제법을 자동 해금하지 않는다.
