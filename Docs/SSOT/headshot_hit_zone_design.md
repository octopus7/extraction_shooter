# 헤드샷 피격 구역 설계

이 문서는 TunaSweeper의 헤드샷과 세부 피격 구역 판정 기준을 정리하는 SSOT 문서다.

## 핵심 기준

- 헤드샷은 에임 상태 전용 기능이 아니다.
- 힙파이어라도 조준 의도와 실제 탄도 결과가 모두 머리로 판정되면 헤드샷으로 처리한다.
- 에임 상태는 헤드샷을 해금하지 않고, 스프레드와 리코일을 줄여 머리 피격 구역을 맞힐 확률만 높인다.
- 판정은 발사 순간의 커서 방향, 리코일, 스프레드가 모두 반영된 최종 탄도를 기준으로 한다.
- 조준 의도 없이 긴 사선이 머리 구역을 스치기만 하는 경우는 헤드샷으로 보지 않는다.

## 판정 방식

- 모든 피격 대상은 넉넉한 기본 피격 구역을 가진다.
- 헤드샷 가능한 대상만 별도 헤드샷 프로필을 가진다.
- 머리 개념이 애매한 대상은 기본 피격 구역만 사용하고 헤드샷 대상에서 제외할 수 있다.
- 세부 피격 구역 우선순위는 `Head > Critical > Body`로 본다.
- 투사체가 기본 피격 구역에 먼저 맞은 대상만 세부 피격 구역 판정 대상이 된다.
- 헤드샷은 `Head Intent`와 `Head Core`를 모두 만족할 때만 적용한다.
- `Head Intent`는 리코일이 적용된 크로스헤어가 머리를 노렸는지 보는 2D 판정이다.
- `Head Core`는 스프레드까지 반영된 최종 탄도선이 실제 피격 대상의 머리 중심부를 통과했는지 보는 탄도 판정이다.
- 세부 판정은 전체 무한 사선이 아니라, 해당 대상 내부의 실제 피격 구간에서만 수행한다.
- `Head Intent`는 조준 의도 확인용이므로 `Head Core`보다 약간 넓게 둘 수 있다.
- 탄환 반지름이나 넉넉한 기본 피격 구역은 명중 보정에는 쓰되, 헤드샷 판정을 과하게 넓히는 데 쓰지 않는다.
- 여러 구역을 동시에 통과하면 가장 높은 우선순위 구역을 적용한다.

## 탑다운 보정

- 수평 투사체의 실제 Z 충돌만으로 머리 판정을 결정하지 않는다.
- `Head Intent`는 화면 기준 2D 프록시로 처리한다.
- `Head Core`는 대상 내부의 작은 탄도 교차 프록시로 처리한다.
- 프록시는 대상 몸체 안에서만 유효하며, 대상 바깥을 지나가는 사선 교차는 무시한다.
- 데미지 판정 위치와 피격 이펙트 위치는 분리한다.
- 피격 이펙트는 허공 판정점이 아니라 보이는 메시 표면 또는 별도 앵커 위치로 보정한다.

## 발사 파이프라인

- 발사 시 먼저 리코일이 적용된 크로스헤어 위치로 2D 조준 판정을 수행한다.
- 이 2D 조준 판정에서 맞은 대상과 부위를 결정한다.
- 조준 부위가 정해지면, 무기 발사점에서 해당 부위 높이의 목표점으로 상하 발사각을 만든다.
- 그 다음 스프레드를 적용해 최종 탄도를 확정한다.
- 스프레드가 거의 없으면 탄은 리코일 적용 크로스헤어가 가리킨 부위에 피탄되어야 한다.
- 스프레드가 있으면 조준 부위와 다른 부위에 맞거나 빗나갈 수 있다.
- 헤드샷은 조준 판정이 `Head Intent`이고, 스프레드 적용 후 최종 탄도가 `Head Core`를 통과할 때만 성립한다.

## 구현 원칙

- 기본 피격 구역은 실제 명중을 받는 판정이다.
- `Head Intent`와 `Head Core`는 실제 명중을 가로채지 않는 보조 판정 데이터다.
- 최종 발사 탄도는 한 번만 확정하고, 피해 판정과 시각 피드백이 같은 결과를 공유한다.
- 리코일 적용 크로스헤어가 `Head Intent` 밖이면 헤드샷이 아니다.
- 스프레드 적용 최종 탄도가 `Head Core` 밖이면 헤드샷이 아니다.
- 에임하지 않아도 두 조건을 모두 만족하면 헤드샷이다.
- 헤드샷 디버그에서는 리코일 적용 크로스헤어, 최종 탄도선, 실제 피격 대상, 기본 피격 구역, `Head Intent`, `Head Core`를 함께 볼 수 있어야 한다.
