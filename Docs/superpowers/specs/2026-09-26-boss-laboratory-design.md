# 싱글플레이 보스 연구실

## 확정된 범위

메인 메뉴의 `연구실`에서 `보스개발`, `보스플레이(싱글)`, 아래쪽 `보스플레이(멀티)`로 진입한다. 멀티 버튼은 `개발 중` 토스트만 표시한다. EOS, RPC, 복제, 온라인 전송은 이번에 구현하지 않는다.

보스개발은 게임 안에서 부품을 연결하고 제한된 전술을 설정해 저장·시험하는 기능이다. 싱글 플레이는 저장된 보스를 선택해 반복 전투한다. 같은 정의/검증/런타임을 두 모드가 공유한다. 시험 장비와 경험치는 기존 combat-test 보호 경로로 본편 진행과 분리한다.

## 데이터와 조립

- 버전 1 정의, 카탈로그 버전 1. 코어, 프레임, 장갑, 구동부, 기관포, 미사일, 레이저의 내장 카탈로그를 사용한다.
- 코어 1개에 연결한 트리, 고유한 정수 인스턴스 ID, 부모 ID, 부모의 6방향 연결부, 90도 단위 yaw로 표현한다. 최대 32개 부품, 최대 깊이 8, 파일 최대 256 KiB, 이름 최대 64자.
- 부품 배치와 기본 수치는 카탈로그에서 도출한다. 정의에 외부 에셋/코드/클래스 경로를 넣지 않는다. 순환·중복 연결부·알 수 없는 부품·범위 밖 값·과도한 공간 크기를 거절한다.
- 전술은 균형/거리 유지/접근 프리셋, 공격 간격, 2페이즈 체력 기준, 교대/동시 무장 사용을 제공한다. 공격 예고와 실행 예산을 제한한다.
- 부위 내구도와 공격 상태는 정의와 별개다. 부모 파괴는 해당 하위 부품 기능을 정지시킨다. 코어 파괴로 승리한다.

## 보관

12개 보스 슬롯을 게임 진행 슬롯과 별도로 관리한다. `Saved/BossLab/<Demo|Main>/Slot01.boss.json`부터 슬롯별 단일 JSON을 저장한다. 목록은 파일에서 재구성하여 외부 파일 복사 후 새로고침으로 인식한다. 유효하지 않은 파일은 보존하고 오류를 표시한다. 슬롯 교체와 삭제는 사용자의 명시적 동작을 요구하며 실패한 저장이 정상 파일을 파괴하지 않도록 후보 파일을 검증하고 교체한다.

## 화면과 전투

타이틀 연구실 메뉴에서 선택 후 기존 BossCombatTestMap에 전용 게임 모드로 진입한다. 기존 자동 보스전은 비활성화한다. 작업 화면은 슬롯/부품/연결/전술 조작 패널과 월드의 3D 보스 미리보기를 함께 제공한다. 저장·불러오기·복제·부품 제거·파일 폴더 열기·시험·타이틀 복귀를 지원한다. 편집 초안은 시험 왕복 동안 유지한다.

새 UI는 기존 UI 문자열 CSV와 ResolveLocalizedText, 공용 폰트를 사용한다. 시스템 메시지와 오류 역시 키로 표현한다. 사용자 입력 보스 이름만 사용자 데이터로 표시한다.

전투는 플레이어 한 명과 조립 보스 한 기다. 이동은 제한된 지상 구동으로 시작하고 회전/접근/거리 유지와 무기 공격을 제공한다. 피격 컴포넌트를 부품 ID에 매핑한다. 전투 시작은 검증된 정의를 복사하여 고정하며 화면에 떠 있는 초안을 실시간 참조하지 않는다. 전투 종료/재시작은 모든 공격과 임시 상태를 정리한다.

## 검증

정의 JSON 왕복, 잘못된 파일·버전·연결·수치, 유한 슬롯 경계, 덮어쓰기와 실패 보존, 부위 파괴·코어 승리·재시작, 메뉴 순서·멀티 토스트, 문자열 키, 패키징 맵 포함을 확인한다. 에디터 빌드와 관련 자동화 테스트를 실행하고 가능한 범위에서 화면을 확인한다. 생성기 없이 native runtime UI/조립을 사용한다.

## 작업 원칙

현재 체크아웃의 다른 진행 중 변경을 보존한다. 이번 구현·검증·문서·요청 기록을 하나의 커밋으로 정리하며 네트워크 동작을 추가하지 않는다.
