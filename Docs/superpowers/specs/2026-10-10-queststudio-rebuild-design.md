# QuestStudio 재구성 설계

## 목표와 기준

프로젝트 로컬 퀘스트 데이터를 SSOT로 유지한다. QuestStudio는 사용자가 직접 파일을 가져오고 내보내는 보조 툴이며, 챕터별 퀘스트 연결을 확인하고 선행 번호를 입력하거나 기존 연결을 해제하는 데 집중한다. 장소 편집, 이동 동선, 시간 시뮬레이션은 제공하지 않는다.

사용자는 UE의 기존 데모 퀘스트도 삭제·교체하는 범위임을 확인했다. 게임의 기존 데모 퀘스트 정의와 해당 퀘스트에 종속된 자동 수락·종료 조건 및 검증을 함께 정리한다. 기존 맵의 사용자 변경은 보존한다.

## 데이터와 공개 경계

- 저작 데이터는 상위 journal의 지정된 두 지역 퀘스트 원문을 기준으로 구성한다. 원문에 명시되지 않은 선행조건, 게임 이벤트 ID, 아이템 ID 및 실행 조건은 임의로 확정하지 않는다.
- 지역별 원문 번호를 유지하여 `R1-01`, `R2-01` 형태의 퀘스트 ID를 사용한다. 원문에서 확인된 선행조건만 입력하고, 불명확한 조건은 저작 메타데이터에 미정으로 남긴다.
- 미공개 본편의 노드·문자열·출처 정보는 실제 접근 제한 로컬 저장소인 `TunaSweeper/External/MainPayload/Authoring/QuestStudio/`에 보관한다. 공용 툴 소스, 테스트 fixture, 정적 번들 및 데모 빌드에 본편 내용이 포함되지 않게 한다.
- 이 작업은 원문 기반 저작 노드를 구성한다. 미정 게임 이벤트를 새로 구현하거나 저작 초안을 실행 가능한 게임 퀘스트로 자동 적용하지 않는다. 게임용 데이터 반영은 명시적인 익스포트/적용 단계로 둔다.
- 새 콘텐츠 문자열은 한국어만 작성한다. 빈 번역을 기계 번역하거나 한국어를 다른 언어 칸에 복사하지 않는다. 기존 공용 UI 문자열 및 관련 없는 번역은 보존한다.

## 저작 메타데이터와 연결

- 기존 퀘스트 정의 객체를 보존하고 `authoring_tags`에 `chapter:1` 같은 챕터 태그를 추가한다. 이 태그는 게임의 수락, 목표 진행, 보상 및 세이브 판정에 사용하지 않는다. 기존 UE JSON 로더가 알 수 없는 필드를 무시하는 동작을 유지한다.
- 선행관계의 저장 필드는 기존 `required_completed_quest_ids`다. 후행관계와 화면 연결선은 이 목록에서 계산한다.
- 툴 전용 위치, 출처 및 선행조건 확인 상태는 노드의 저작 메타데이터로 보존한다. 게임 실행 의미와 분리한다.
- 선택 챕터의 노드만 펼쳐 보여준다. 다른 챕터의 직접 선행 퀘스트는 번호와 `다른 지역` 표시를 가진 경계 노드로 보여주고, 그 노드의 선행까지 재귀 확장하지 않는다.
- 챕터 필터는 표시만 바꾼다. 저장·익스포트에는 숨겨진 챕터와 관계도 전부 포함한다.
- 같은 챕터에서는 `01`처럼 원문 번호를 입력할 수 있고, 다른 챕터는 `R1-20`처럼 전체 번호를 입력한다. 없는 번호는 오류로 처리하며 작업 데이터에 반영하지 않는다. 자기 자신, 중복 및 순환 관계도 거부한다.
- 연결 편집은 번호 입력과 연결 해제에 한정한다. 드래그로 연결 생성, 노드 생성/삭제 및 퀘스트 본문 편집은 이번 범위에 포함하지 않는다.

## 스냅샷과 수동 교환

작업물 테이블은 다음 세 가지다.

| 테이블 | 키 | 내용 |
| --- | --- | --- |
| `snapshots` | 고유 `id` | 별칭, 메모, 저장 시각, 교환 포맷 버전 |
| `quest_nodes` | `(snapshot_id, quest_id)` | 전체 정의 JSON, 저작 메타데이터, 배치 좌표 |
| `localization_strings` | `(snapshot_id, string_key, locale)` | 문자열 값 |

- 스냅샷은 전체 노드와 전체 문자열을 함께 저장하며, 명시적인 저장마다 새 ID를 만든다. 저장된 작업물은 덮어쓰지 않는다.
- 조회·복원은 특정 스냅샷 하나를 기준으로 하며, 개별 노드의 최신 수정 시각을 섞지 않는다.
- 새 스냅샷 저장은 완전한 데이터가 검증되고 모두 기록됐을 때만 성공한다. 실패 시 불완전한 스냅샷을 노출하지 않는다.
- 사용자는 파일 가져오기, 파일 내보내기, D1 스냅샷 저장, 스냅샷 불러오기를 직접 실행한다. 시작·빌드·로그인 시 자동 시드, 동기화, 게시 또는 로컬 SSOT 덮어쓰기를 하지 않는다.
- 문자열과 선행 참조는 같은 스냅샷 안에서 검증한다. 전체 정의의 알 수 없는 필드도 왕복 교환 시 보존한다.

## 인증과 UI

- 기존 `ADMIN_PASSWORD` 및 관리자 세션 방식을 유지한다. 작업물 API는 관리자 인증을 요구한다.
- 비밀번호는 Worker Secret에 두고, D1에는 난수 세션의 해시만 저장한다. 기존 세션 만료, 로그인 실패 제한, 보안 쿠키 및 동일 출처 검증을 유지한다.
- 인증용 `admin_sessions`, `admin_login_attempts`는 위 세 작업물 테이블과 별도의 기반 테이블이다.
- 화면은 로그인, 스냅샷/파일 작업 바, 챕터 선택, 확대·이동 가능한 노드 그래프, 선택 노드의 읽기 전용 상세 및 선행 번호 편집으로 구성한다.
- 모든 UI 문구와 오류는 문자열 키로 해결한다. `다른 지역`, `선행 미정`, 없는 번호 오류도 예외가 아니다.

## 검증과 완료 범위

- 원문 번호와 노드 개수, 한국어 문자열 참조, 확정 선행관계, 미정 상태 보존을 확인한다. 서사 검증 자료는 접근 제한 저장소에만 남긴다.
- 존재하지 않는 번호, 자기 참조, 중복, 순환, 챕터 외 경계 표시, 필터 후 전체 데이터 보존, UTF-8 및 JSON/CSV 왕복을 검사한다.
- 스냅샷 전체 저장·복원 및 실패 시 원자성, 로그인 성공/실패·만료·접근 제한을 검사한다.
- 데모 제거로 깨지는 게임 참조·회귀 테스트를 정리하고 필요한 UE 검증을 수행한다. UE를 빌드하면 완료 후 해당 프로젝트 에디터를 연다.
- 툴 테스트·프로덕션 빌드·Wrangler dry run을 수행한다. 이번 요청에서 원격 D1 콘텐츠 변경/게시를 자동 실행하지 않는다. 배포를 진행하는 경우 프로젝트 규칙에 따라 검증된 소스를 먼저 커밋·푸시한다.
- 원본 조사, 공용 툴, 게임 데모 정리를 서로 다른 파일 범위로 나누어 병렬 구현한다. 각 저장소의 변경과 해당 기록은 검증 후 저장소별 단일 작업 커밋으로 묶는다.
