# EOS 기반 Steam 래핑 2인 코옵 설계

- 상태: 구현 전 승인 설계
- 대상: Unreal Engine 5.7 TunaSweeper
- 범위: 호스트 1명 + 헬퍼 1명, 별도 매칭 서버 없음

## 목표

Steam으로 실행한 두 사용자가 EOS Connect를 통해 공통 온라인 사용자 식별을 얻고, 호스트가 생성한 8자리 숫자 코드를 헬퍼에게 알려주면 헬퍼가 해당 방에 참가해 호스트 리슨 서버에 접속한다. EOS는 인증·로비/세션 검색·접속 정보 전달을 담당하고, 게임 서버 프로세스는 만들지 않는다. 오프라인 싱글플레이는 EOS 장애와 분리한다.

## 비목표

첫 구현에서는 코옵 전투 권한, 헬퍼 인벤토리 격리, 저장 정산, 재접속 복구, 음성, 공개 방 목록, 자동 랜덤 매칭, 전용 서버를 구현하지 않는다. 이 기능들은 연결 기반이 안정화된 뒤 별도 설계한다.

## 아키텍처

`UTunaSweeperOnlineCoopSubsystem`은 `UGameInstanceSubsystem`으로 로그인 상태, 방 상태, 초대 코드, 세션 콜백, 호스트/헬퍼 전환을 소유한다. 공개 API는 Blueprint 호출이 가능한 호스트 생성, 코드 검색/참가, 방 종료, 현재 코드·상태 조회 함수와 델리게이트로 제한한다.

`FTunaSweeperPlatformAuthAdapter`는 플랫폼별 자격증명 획득 경계를 둔다. 첫 구현은 Win64 Steam 경로를 사용해 Steam Web API 세션 티켓을 얻고 EOS Connect 외부 자격증명으로 변환한다. 티켓·EOS 토큰·비밀 값은 로그, 로비 속성, 저장 파일에 기록하지 않는다. EOS/Steam SDK가 없거나 인증이 실패하면 서브시스템은 명시적인 실패 상태를 내고 싱글플레이 진입을 막지 않는다.

온라인 세션은 UE `IOnlineSession`/`OnlineSubsystemUtils` 인터페이스를 통해 생성·검색·참가한다. 호스트 세션은 `bShouldAdvertise`, `bAllowJoinInProgress=false`, `NumPublicConnections=2`, 리슨 서버 옵션을 사용한다. 세션 검색 속성에는 임의로 생성한 8자리 ASCII 숫자 코드의 해시 또는 검색 가능한 EOS 로비 속성만 저장하며, 원본 코드 외에는 사용자 식별 정보를 노출하지 않는다. 검색 결과는 코드 완전 일치와 게임/데이터 프로토콜 버전 일치를 모두 통과해야 참가한다.

참가 성공 뒤 `GetResolvedConnectString`이 반환한 주소를 사용해 `ClientTravel`한다. 세션 콜백과 travel 실패는 모두 중복 완료를 방지하는 단일 상태 전이로 처리한다. 호스트 종료·세션 파괴·EOS 로그아웃 시 코드는 무효화한다.

## 상태 및 데이터 흐름

1. 게임 인스턴스가 EOS/Steam 온라인 서브시스템을 확인한다.
2. Steam 티켓을 EOS Connect에 로그인해 PUID를 얻는다.
3. 호스트가 00000000~99999999 범위에서 예측하기 어려운 코드를 생성하고 세션을 연다.
4. 세션 생성 성공 시 UI에 코드와 대기 상태를 알린다.
5. 헬퍼가 숫자 8자리만 허용하는 입력 검사를 통과하면 세션 검색을 실행한다.
6. 검색 결과에서 코드·프로토콜 버전·인원 여유를 검증하고 JoinSession을 호출한다.
7. 접속 문자열을 해석해 호스트 리슨 서버로 이동한다.
8. 어느 단계든 실패하면 세션 상태를 실패로 만들고 재시도 가능한 오류 키를 전달한다.

코드는 세션 자체의 보안 토큰이 아니다. 방 코드가 노출되면 누구나 검색을 시도할 수 있으므로 EOS 로비 권한과 최대 인원 제한을 신뢰 경계로 사용하고, 이후 단계에서 플랫폼 초대나 소유자 승인 UI를 추가할 수 있다.

## 설정 및 종속성

프로젝트는 `OnlineSubsystemEOS` 플러그인과 `OnlineSubsystemUtils` 모듈을 명시한다. EOS 제품 ID, 샌드박스 ID, 배포 ID, 클라이언트 자격증명은 추적 파일에 기록하지 않고 로컬/패키징 환경 설정으로 주입한다. 기본 배포 설정은 Steam을 유지하며 EOS를 사용할 수 없는 환경에서는 온라인 코옵 버튼만 비활성화한다.

## 오류 처리

오류는 인증 실패, 서비스 초기화 실패, 세션 생성 실패, 코드 형식 오류, 코드 불일치, 방 가득 참, 버전 불일치, 접속 문자열 실패, travel 실패로 구분한다. 각 오류는 안정적인 enum과 문자열 키를 가지며 UI는 `UTunaSweeperTextSubsystem`으로 번역한다. 네트워크 콜백이 늦게 도착하거나 중복 도착해도 현재 상태와 작업 세대가 맞지 않으면 무시한다.

## 검증

자동화 검증은 코드 생성 범위·8자리 형식·세션 설정·검색 결과 필터·상태 전이 중복 방지를 다룬다. 에디터/실행 검증은 EOS 자격증명이 있는 Win64 환경에서 호스트 1개와 헬퍼 1개를 실행해 로그인, 방 생성, 코드 검색, 참가, 리슨 서버 travel, 방 종료를 확인한다. EOS 자격증명이 없는 CI에서는 온라인 테스트를 건너뛰고 컴파일·순수 함수 테스트만 실행한다.

## 구현 순서

1. EOS 플러그인/모듈 및 설정 경계를 추가한다.
2. 코드 생성·세션 설정·오류 enum과 순수 테스트를 추가한다.
3. 온라인 코옵 서브시스템과 Steam→EOS 인증 어댑터를 구현한다.
4. 게임 인스턴스/메뉴에서 생성·참가 API를 연결하고 문자열 키를 추가한다.
5. 빌드와 자동화 검증을 실행하고 실제 EOS 자격증명 환경의 수동 체크리스트를 문서화한다.
