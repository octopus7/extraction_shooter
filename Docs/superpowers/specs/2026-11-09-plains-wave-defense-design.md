# 3지역 평원 — 1인 웨이브 거점 방어 미니게임 설계안

작성일: 2026-11-09  
상태: 검토용 설계안. 게임 코드·맵·에셋은 아직 변경하지 않았다.  
구현 계획: [단계별 구현 계획](../plans/2026-11-09-plains-wave-defense.md)

## 1. 요청과 설계의 구분

**사용자가 정한 내용**

- `/Game/MainRaid/RaidPlains`인 3지역 평원에서 플레이한다.
- 혼자 플레이하는 웨이브 방식의 거점 방어 미니게임이다.
- SSTO 부속 시설이 아니라 **평원에 독립된 새 거점을 조성한다.**
- 이번 작업은 계획과 문서 작성이다.

**이 문서에서 제안하는 내용**

- 선택적으로 시작하는 6웨이브, 목표 플레이 시간 10~15분.
- 중앙의 방어 장치 1개를 보호하고, 고정 설치 지점에 방벽과 자동 포탑을 배치한다.
- 실제 보유 장비·소모품으로 참여한다. 시설 설치에는 회차 전용 자원을 사용한다.
- 성공 보상은 기본 300코인, 실패 보상은 없다. 전투 중 사망에는 기존 레이드 사망 규칙을 적용한다.

위 수치·보상·사망 정책은 사용자 확정 사항이 아니다. 구현 전에 수정할 수 있는 기준안이며, 최종 난이도는 실제 플레이로 조정한다. 호드에서 참고하는 것은 준비→습격→재정비의 흐름이다. 다인 역할군이나 긴 50웨이브 구조까지 가져오지는 않는다.

## 3. 선택한 방향과 대안

| 방식 | 장점 | 비용·한계 | 판단 |
| --- | --- | --- | --- |
| 기존 SSTO 주변에 방어 장치 설치 | 기존 랜드마크 활용, 환경 제작량 감소 | 사다리·기존 진행 동선과 충돌할 수 있음 | 사용자가 독립 거점을 선택했으므로 채택하지 않음 |
| 평원 안에 독립 거점 + 유한 웨이브 | 탐험 중 발견하는 선택 활동, 혼자서 끝까지 완주 가능 | 별도 거점·침입로 제작 필요 | 독립 거점은 사용자 선택, 6웨이브는 작성자 추천 |
| 독립 거점 + 무한 웨이브 | 반복 기록 경쟁에 적합 | 장시간 밸런스·보상 파밍·스폰 확장 부담 | 완주형 검증 후 확장 후보 |

1차 범위는 거점 1곳, 방어 장치 1개, 진입로 3개, 시설 2종, 난이도별 기존 전투 배율 연동, 결과 기록·보상이다. 멀티플레이, 동료 NPC 고용, 자유 건축, 전용 보스 제작, 영구 시설 강화, 별도 스킬 트리·재화·스토리 퀘스트는 포함하지 않는다.

## 4. 공간 구성

거점 이름은 기획상 **평원 방어 거점**으로 둔다. 방어 대상은 교체 가능한 독립 장치이며, 특정 서사나 SSTO 수리 기능을 부여하지 않는다.

| 구역 | 초안 크기·역할 |
| --- | --- |
| 중앙 장치와 조작 단말 | 중심에서 반경 5m, 사방 접근 가능 |
| 방어 진지 | 반경 8~15m, 낮은 엄폐물과 순환 이동로 |
| 진입로 | 북·동·서 3방향, 각 방향에 방벽 슬롯 1개와 포탑 슬롯 1개 |
| 적 생성 후보 | 중심에서 28~38m, 진입로당 2곳 이상; 플레이어와 최소 15m 이격 |
| 활동 경계 | 중심 반경 45m를 기본값으로 하는 편집 가능한 볼륨 |
| 일반 출입로 | 남쪽 개방 통로, 평상시 탐험 동선과 연결 |

아래 그림은 **거점 로컬 배치 개념**이며 실제 맵의 확정 좌표가 아니다.

```text
                       북 +X
                   침입로 A / 생성 후보
                          ↓
                    방벽 A · 포탑 A
                          │
 서 -Y   침입로 B → 방벽 B · 중앙 장치 · 방벽 C ← 침입로 C   동 +Y
                      포탑 B       포탑 C
                          │
                    단말 / 남쪽 출입로
                       남 -X
```

- SSTO·사다리 양 끝·리프트 도착점·메모·탈출 접근로와 겹치지 않는 외곽 후보지를 우선 조사한다. 특정 방위나 좌표는 아직 확정하지 않는다.
- 이동 경계 안에 활동 볼륨과 생성 후보를 모두 수용하고, 기존 통로에는 최소 5m 보행 여유를 남기는 것을 목표로 한다.
- 적 생성은 지형·가림막 뒤에서 한다. 카메라 화면 안이거나 플레이어와 너무 가까우면 다른 후보를 선택한다. 잠깐 보이지 않는다는 이유만으로 플레이어 뒤에 생성하지 않는다.
- 방벽 양옆에 적이 우회할 수 있는 길을 남긴다. 고정 메시 충돌과 내비게이션 설정으로 완전 봉쇄를 피하고, 1차에서는 자유 건축에 따른 동적 NavMesh 재구성을 요구하지 않는다.
- 엄폐물은 이동·사선 차단용이다. 새로운 엄폐 조작 시스템을 추가하지 않는다.
- 구현 시 저장된 맵을 재로드해 지면 충돌, 실제 카메라, 사다리·탈출 동선, 세 진입로의 경로를 검사한다. 모든 조건을 만족하는 위치가 없으면 기존 콘텐츠를 임의로 옮기지 말고 거점 크기를 조정한다.

## 5. 한 회차의 진행

1. 단말에서 규칙·보상·기존 사망 손실을 확인하고 시작한다. 자동 시작하지 않는다.
2. 시작 기록을 저장한 뒤 장치 내구도와 회차 자원을 초기화하고 45초 준비 시간을 준다.
3. 다음 공격 방향과 적 구성을 표시한다. 준비 완료 버튼으로 대기 시간을 줄일 수 있다.
4. 웨이브 중에는 실제 무기 전투로 적을 처치한다. 장치 수리와 시설 설치는 준비 시간에만 허용한다.
5. 생성 예정 수가 0이고 살아 있는 회차 적도 0이면 웨이브를 완료한다. 죽은 몸체의 디졸브 종료를 기다리지 않는다.
6. 1~5웨이브 종료마다 자원 100을 지급하고 30초 재정비한다. 장치 내구도는 자동 회복하지 않는다.
7. 6웨이브 종료 후 성공 결과를 저장하고 보상 수령을 제공한다. 평원 탐험을 계속하거나 기존 탈출 지점으로 귀환한다.

시작 조건은 플레이어 생존·도보 상태, 다른 회차 없음, 미수령 보상 없음, 필수 참조와 생성 경로 유효이다. 또한 활동 구역 안에 기존 적이 남아 있거나 플레이어가 교전 중이면 시작을 막는다. 시작 실패는 코인·아이템·회차 자원을 소비하지 않는다.

준비·공격·이탈 제한 시간은 월드 게임 시간을 사용한다. 일시정지 시 멈추며 슬로모션은 월드와 함께 느려진다. 기존 인벤토리 UI의 일시정지 여부를 미니게임만 다르게 바꾸지 않는다.

| 웨이브 | 장치 압박 근접병 | 플레이어 견제 사수 | 강화 근접병 | 총수 | 동시 생존 상한 | 공격 방향 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 4 | 2 | 0 | 6 | 4 | 1방향 |
| 2 | 5 | 3 | 0 | 8 | 5 | 다른 1방향 |
| 3 | 6 | 3 | 1 | 10 | 6 | 2방향 |
| 4 | 7 | 5 | 0 | 12 | 7 | 2방향 교대 |

| 6 | 9 | 5 | 2 | 16 | 8 | 3방향을 순차 사용, 동시 활성은 최대 2방향 |

합계 66마리. 한 번에 최대 2마리, 배치 사이 기본 3초로 나누어 생성하며 생존 상한이 차면 기다린다. 방향 변경은 최소 5초 전에 표시한다. 공격 자체의 시간제한은 두지 않는다. 전투당 60~100초와 준비 시간 합계 195초를 기준으로 전체 10~15분을 목표로 한다. 목표 시간을 맞추기 위해 무적 대기나 체력만 큰 적을 추가하지 않는다.

강화병은 기존 일반 근접 적의 별도 프로필로 체력 1.5배를 우선 시험하고 피해·속도는 유지한다. 새 보스나 복잡한 차량·스포너 적은 1차 명단에서 제외한다. 실제 클래스·전투 프로필·무기는 공개 일반 전투 에셋을 검증해 DataAsset에 지정하며, 기존 Main 퀘스트 적 구성을 복사하지 않는다.

## 6. 혼자서 방어할 수 있게 만드는 규칙

### 방어 장치와 AI

- 장치 내구도 초안은 1000, 자동 회복 없음. 유효한 회차 적의 실제 피해만 받으며 플레이어·포탑·동료·일반 탐험 적의 피해는 받지 않는다.
- 근접병은 기본적으로 장치로 이동한다. 진행로의 방벽이 가까이서 가로막으면 먼저 공격한다. 플레이어가 8m 안에 있거나 최근 3초 안에 자신을 공격했으면 플레이어에게 대응하고, 조건이 끝나면 장치 공격으로 복귀한다.
- 사수는 플레이어를 우선 견제한다. 플레이어가 보이지 않으면 거점 안의 사격 지점까지 이동하고 보이는 장치를 공격한다. 장치 위치를 알고 있다는 이유로 벽을 관통해 쏘지 않는다.
- 공격 사선·방향 정렬·재장전·근접 거리·피해 반올림·팩션 판정은 기존 전투 규칙을 유지한다. 보행 목표까지의 이동 의도와 실제 공격 가능 여부는 분리한다.
- 장치·방벽·포탑이 받는 적 피해에도 시작 난이도의 기존 적 피해 배율을 정확히 한 번 적용한다. 플레이어 피해는 기존 경로를 그대로 사용한다. 구조물에 별도 방어력·헤드샷 배율은 두지 않고 마지막에 정수 피해로 반올림한다. 따라서 높은 난이도에서는 시설 방어도 어려워지는 초안이다.
- 미니게임 목표 지정은 회차 적에만 적용한다. 일반 탐험 적이 새 장치에 유인되지 않도록 대상 적격성도 제한한다.
- 기존 펫이 동행한다면 기존 행동을 유지하되 필수 전력으로 계산하지 않는다. 회차 적의 사망은 처치 주체와 관계없이 정확히 한 번 집계한다. 차량 탑승 시 회차를 포기 처리한다.

### 회차 자원과 시설

HUD 명칭은 **방어 자원**이다. 인벤토리 아이템이나 코인이 아니며 저장·거래·반출하지 않는다. 시작 200, 1~5웨이브 완료마다 100, 총 공급 700이다. 처치별 추가 지급은 없다.

| 행동 | 비용 | 초기 규칙 |
| --- | ---: | --- |
| 방벽 설치·파괴 후 재설치 | 50 | 내구도 300, 진입로별 고정 슬롯 1개 |
| 포탑 설치·파괴 후 재설치 | 150 | 내구도 250, 최대 2기, 슬롯은 3개 중 선택 |
| 장치 수리 | 50 | 내구도 200 회복, 최대치 초과분은 버림 |
| 시설 수리 | 25 | 해당 시설 내구도 50% 회복, 최대치 초과분은 버림 |
| 포탑 재장전 | 50 | 회차 전용 60발로 보충, 남은 탄에 더하지 않음 |

포탑은 설치 시 60발, 1초에 1발, 사거리 18m, 기본 피해 10의 실제 투사체를 사용하는 초안이다. 사선이 확보된 현재 회차 적만 겨냥하며 일반 탐험 적을 자동 사냥하지 않는다. 적의 원거리 공격에는 피격될 수 있다. 시설 피해도 장치와 같은 회차 소유권 검사 후 기존 피해 함수를 거친다.

설치·수리·보충은 준비 시간에 단말에서 즉시 처리한다. 자원 부족·슬롯 중복·체력/탄약이 이미 가득 찬 요청은 무소모로 거절한다. 철거·환불·시설 이동은 1차에서 제공하지 않는다. 종료 시 모든 회차 시설을 제거하고 슬롯 표시만 남긴다.

플레이어 탄약·치료제·허기·수분은 기존 규칙대로 소모한다. 무료 탄약이나 임시 아이템을 지급하지 않는다. 시작 안내에 준비 필요성을 표시한다. 보급 부족이 시험 플레이의 주된 실패 원인이면 웨이브 수·적 체력·보상부터 조정하고, 전용 보급품 시스템은 별도 범위로 검토한다.

## 7. 실패·중단·복구

| 상황 | 결과 |
| --- | --- |
| 장치 내구도 0 | 실패, 보상 없음, 플레이어는 평원에 남음 |
| 플레이어 사망 | 실패, 기존 레이드 사망·소지품 손실·귀환 처리 유지 |
| 단말 또는 메뉴에서 포기 | 중단, 보상 없음, 별도 벌금 없음 |
| 활동 경계 밖에서 10초 경과 | 이탈 안내 후 중단; 경계 안으로 복귀하면 카운트 취소 |
| 지역 이동·탈출·차량 탑승 | 중단 및 회차 정리; 기존 이동 자체를 영구 잠그지 않음 |
| 메뉴 종료·프로세스 중단·진행 중 세이브 재로드 | 진행 재개 없음; 다음 로드에서 진행 기록을 중단으로 정리 |
| 정상 종료 이후 재도전 | 결과 닫기 및 미수령 보상 해결 후 새 회차 시작 |

동일 프레임에 마지막 적 사망과 장치 파괴/플레이어 사망이 겹치면 실패를 우선한다. 스폰 소진·사망 이벤트 직후 즉시 성공시키지 말고 해당 프레임의 치명 조건을 확인한 뒤 종결한다. 이미 저장된 성공과 미수령 보상은 이후 일반 탐험 중 사망으로 취소하지 않는다.

정리는 회차가 소유한 적·컨트롤러·무기·발사체·시설·타이머·HUD·델리게이트만 대상으로 한다. 일반 탐험 적이나 기존 상자는 삭제하지 않는다. 적 제거는 정상 처치 함수 호출 없이 실행하여 보상·퀘스트·사망 드롭을 만들지 않는다.

### 진행 정체 대응

- 생성 후보마다 NavMesh 투영, 지면 캡슐 여유, 장치까지 도달 경로, 플레이어 거리와 화면 노출을 검사한다.
- 모든 후보가 막히면 2초마다 다시 시도하고 15초 후에도 실패하면 시스템 오류로 중단한다. 생성하지 못한 적을 처치로 계산하지 않는다.
- 적이 교전도 하지 않고 10초간 경로 진행도 없으면 다른 경로를 요청한다. 추가 10초에도 회복되지 않으면 화면 밖의 유효 후보로 같은 개체를 재배치하되 남은 체력을 유지한다. 유효 후보가 없으면 오류 중단한다.
- 정상 사망이 아닌 회차 적의 예기치 않은 삭제는 자동 클리어로 처리하지 않는다. 정리 중 삭제와 구분하여 오류 중단한다.
- 오류 중단에는 원인 키를 표시하고 개발 로그에 회차·웨이브·적 슬롯·후보를 남긴다. 이미 소비한 플레이어 소모품을 자동 복원하지 않는다.

## 8. 보상·기록·저장 계약 제안

1차 성공 보상은 **300코인**이다. 기존 `QuestCoinBalance` 경로를 사용하고, 별도 화폐·경험치 보너스·보상 상자는 만들지 않는다. 난이도 변경은 진행 중 금지하고 시작 당시 난이도를 기록한다. 1차는 난이도별 보상 차등 없이 기존 전투 배율만 적용한다. 재도전 성공마다 지급하되, 목표 플레이 시간의 수익률과 탄약 비용은 밸런스 검증 항목이다.

반복 처치를 통한 우회 보상을 막기 위해 회차 적은 일반 전리품·무기 드롭·회복 드롭·레이드 경험치·퀘스트 처치·업적 처치를 발생시키지 않는다. 미니게임 결과만 자체 기록한다. 기존 적은 기본 동작을 그대로 유지한다.

| 저장 대상 | 제안 내용 |
| --- | --- |
| 거점별 진행 | 안정적인 `EncounterId=plains.wave_defense.01` |
| 최근 회차 | `RunId`, 시작 난이도, 종료 종류, 완료 웨이브 수, 시작 시 고정한 보상량 |
| 누적 기록 | 성공 횟수, 최고 완료 웨이브; 정상 종결 때만 갱신 |
| 보상 수령 | `bRewardPending`; 성공 저장 때 true, 코인 증가와 같은 저장에서 false |
| 저장하지 않음 | 진행 중 적·발사체·장치 체력·시설·방어 자원·현재 타이머 |

기록은 기존 gameplay save에 새 필드로 추가하고 데이터셋·저장 슬롯 경계를 따른다. 기존 세이브는 빈 기록으로 로드한다. 현재 `SaveVersion=22`는 계획 시점 관찰값이며 구현 때 다른 작업의 변경과 합친 뒤 추가 필드 호환성을 검증한다. 문서 작성만으로 현재 저장 계약을 변경하지 않는다.

**저장 순서**

1. 시작: 새 `RunId`와 진행 중 상태를 저장한다. 실패하면 스폰·준비 시간을 시작하지 않는다.
2. 성공: 동일 `RunId`의 성공·기록·미수령 보상을 한 번 저장한다. 완료 저장 실패 시 전투는 끝낸 채 정산 대기 UI와 재시도를 제공하고 새 회차는 막는다. 성공 보상 확정 안내는 저장 후에만 표시한다.
3. 수령: 기존 코인 값과 회차 기록을 보관하고, 코인 증가 + 수령 플래그 해제를 한 번 저장한다. 실패하면 둘 다 되돌리고 재시도 가능하게 한다. 성공 알림은 저장 이후에만 보낸다.
4. 실패·중단: 보상 없이 결과를 저장한다. 쓰기 실패로 기존 사망·귀환을 막지 않는다. 다음 로드에 진행 중 기록이 남아 있다면 중단으로 정리한다.
5. 성공 후 종료·사망·재로드: 미수령 보상은 유지하고 다음 평원 단말에서 수령한다. 수령 전에는 새 회차를 시작할 수 없다.

**성공 저장 실패 중의 이동 정책:** 정산 대기 결과는 현재 월드에서만 재시도한다. 그 상태에서 사망·탈출·지역 이동·메뉴 종료가 일어나면 저장되지 않은 성공을 폐기하고 Interrupted로 종결하며 보상을 지급하지 않는다. 해당 결과 저장도 실패하면 다음 로드의 Active 정리 규칙을 따른다. 이동을 막지 않으며, 정산 대기 화면에 미저장 결과가 사라진다는 안내를 표시한다. 저장에 성공한 미수령 보상에는 이 규칙을 적용하지 않는다.

프로세스가 성공 결과의 저장 전에 강제 종료되면 성공 보상을 보장하지 않는다. 저장된 성공 결과의 수령은 중복되지 않아야 한다. 세이브 파일의 수동 복제·롤백 방지는 이 로컬 미니게임의 범위가 아니다.

## 9. 화면과 조작

- 단말: 미니게임 설명, 6웨이브, 예상 시간, 성공 보상, 사망 손실, 시작/미수령 보상 수령.
- HUD: 웨이브 `현재/6`, 장치 내구도, 살아 있는 적 수와 생성 대기 수, 공격 방향, 방어 자원.
- 준비 화면: 남은 준비 시간, 다음 적 구성, 시설 슬롯·설치·수리·재장전, 준비 완료.
- 경고: 장치 내구도 30% 이하, 방향 전환 5초 전, 경계 이탈 남은 시간. 시각 표시와 짧은 음향을 함께 제공한다.
- 결과: 성공/실패/중단/오류, 완료 웨이브, 보상, 기록, 수령 저장 실패 시 재시도.
- 단말은 기존 상호작용 입력 경로를 사용한다. 별도의 하드코딩된 F키 이벤트를 추가하지 않는다.

예정 키는 `ui.wave_defense.title`, `.start`, `.wave`, `.core_health`, `.alive`, `.queued`, `.supplies`, `.prepare`, `.ready`, `.build_barrier`, `.build_turret`, `.repair`, `.reload_turret`, `.leave_warning`, `.success`, `.failed`, `.aborted`, `.claim`, `.save_failed`, `.spawn_failed`, `.death_warning` 등이다. 실제 버튼명·수치 포맷·오류·방향 표시까지 키로 관리한다. CSV에는 `ko,en,ja,zh-Hans,zh-Hant,ru`를 모두 작성한다.

새 위젯은 구현 담당자의 **실제 모델명 디렉터리** 아래에 두고 클래스명은 목적+실제 모델명만 사용한다. 소스에는 실제 모델명과 reasoning effort를 기록하며 알 수 없는 값을 추측하지 않는다. WBP에는 모델명 접미사를 붙인다. 위젯 트리는 저장된 Widget Blueprint에서 구성하고 C++은 바인딩·표시 갱신만 수행한다.

## 10. 구현 구조

| 구성 | 책임 |
| --- | --- |
| `UWaveDefenseDefinition` | 웨이브·적 클래스/프로필·수치·시설 비용·보상의 단일 DataAsset |
| `AWaveDefenseDirector` | 한 회차 상태, 소유 개체, 스폰 대기열, 클리어·실패 판정, 정리 |

| `AWaveDefenseCore` | 장치 내구도, 회차 한정 피해 처리 |
| `UWaveDefenseParticipantComponent` | 적/시설/발사체의 회차 소유권, 적 역할, 목표·기본 보상 억제 정책 |
| `AWaveDefenseFacility` | 방벽·포탑 공통 내구도와 슬롯, 포탑 발사/탄약 |

| GameInstance의 전용 파일 | 저장 필드 매핑, 시작/종결/보상 수령 트랜잭션 |
| 목적별 WBP | 단말/준비/결과 패널과 전투 HUD |

기존 맵과 GameMode를 유지하며, 전투 실험실 GameMode의 임시 장비·사망 루프를 본편에 가져오지 않는다. 기존 `EnemySpawnSubsystem` 이름만 보고 웨이브 스케줄러로 가정하지 않는다. 이 서브시스템은 현재 전투 프로필 조회와 유지 중인 루팅 배치 데이터가 주된 역할이다.

새 거점 에셋은 `/Game/MainRaid/WaveDefense/`, 코드 핵심은 `Public/WaveDefense/`·`Private/WaveDefense/`에 둔다. 초기에는 기존 런타임 모듈 안에서 구현하고 별도 범용 플러그인화는 요구하지 않는다. 설정은 DataAsset, 위치는 저장된 맵, 진행은 Director, 영속 데이터는 기존 저장 시스템으로 나눈다.

## 11. 완료 기준과 구현 순서

1. **전투 루프 검증:** 단순 장치·한 진입로·한 웨이브로 시작, 목표 공격·실패·정리를 확인한다.
2. **6웨이브 확장:** 표의 수량·상한·방향 예고·재정비·정체 복구를 구현한다.
3. **시설과 UI:** 고정 슬롯 방벽·포탑, 방어 자원, 편집 가능한 WBP를 연결한다.
4. **저장·보상:** 중복 수령·쓰기 실패·세이브 전환·사망·중단 복구를 자동 검증한다.
5. **평원 배치:** 독립 거점을 제작하고 기존 시설 동선과 세 진입로를 실플레이로 확인한다.
6. **밸런스:** 각 난이도에서 수동 완주·실패·포기를 관찰하고 시간·탄약·장치 피해·포탑 기여를 측정한다.

출시 가능한 1차 범위는 위 여섯 단계 전체다. 단순히 적이 생성되는 것만으로 완료라고 하지 않는다. 자동화는 상태·저장·수량·소유권을 검증하고, 수동 플레이는 혼자서 위협을 읽고 대응할 수 있는지 검증한다. 실제 완주 시간과 최종 수치는 구현 후 기록한다.

이번 문서 작업에서는 에디터 빌드·맵 저장·자동화 실행·실제 플레이 검증을 수행하지 않았다. 커밋은 명시적으로 요청받을 때만 수행한다.
