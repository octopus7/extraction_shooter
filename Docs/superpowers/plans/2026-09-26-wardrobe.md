# Wardrobe Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement the independent runtime, interaction, and asset tasks; root integrates the panel and validates the result.

**Goal:** Let the player change among the six modeled outfits at a wardrobe, with global unlocks and save-specific equipment.

**Architecture:** A data asset defines outfits. A character component applies compatible base and clothing meshes. The existing interaction subsystem opens a HUD panel, and the game instance owns save transactions and global unlock data.

**Tech Stack:** Unreal Engine 5.7, C++, UMG, Blender FBX, Unreal editor Python.

**Spec:** `Docs/wardrobe_system.md`

## Global Constraints

- Localize all player-facing strings by key in ko/en/ja.
- Preserve existing model, face, skeleton, animation, and physics assets.
- Use native transparent PNG thumbnails; no background recoloring or alpha extraction.
- Complete implementation, generated asset validation, generator removal, and task log in one commit.
- Preserve unrelated work in the shared checkout.

## Review Focus

- Switching saves must not reset global unlocks; test with the all-unlocked override disabled.
- Failed loads or saves must not report successful equipment changes.
- Visibility refresh after hiding a player must not restore the old skirt on a new outfit.
- Closing or losing the wardrobe source must restore valid game input without reviving dead-player input.
- A different face skeleton must remain untouched during all outfit changes.
