# Save Tool Implementation Plan

> Execute inline using superpowers:executing-plans and test-driven-development. User requested implementation of the wrapper approach; keep one final task commit.

**Goal:** Add a .NET 10 human CLI and an independently usable UE 5.7 save commandlet.
**Architecture:** Editor-only save service uses native save serialization, data subsystem and fail-closed writes. Editor commandlet supplies a JSON file protocol; the CLI wraps it.
**Tech Stack:** UE 5.7 C++, .NET 10, System.Text.Json, existing CSV string tables.
**Spec:** `Docs/superpowers/specs/2026-10-06-save-tool-design.md`

## Global Constraints

No actual user save edits or bundled loadout presets. Key-based UI text. No save schema/version changes. Preserve unrelated working tree changes. Commit implementation, tests, docs and task log together.

## Review Focus

- Failed multi-item edits must not partially save.
- Full inventory and smaller replacement backpack must not delete items.
- Malformed fields must not silently select defaults or commit.
- Request/response paths must not overwrite save files.
- CLI must preserve argument boundaries, Unicode, exit codes and JSON cleanliness.

## Task 1: Native editing service and commandlet

Files: new `Public/Inventory/TunaSweeperSaveTool.h`, `Private/Game/TunaSweeperSaveTool*.cpp/.h`, `Private/Tests/TunaSweeperSaveToolTests.cpp`, editor `Private/SaveTool/TunaSweeperSaveToolCommandlet.*`; runtime Build.cs conditional JsonUtilities dependency.

Interface: `TunaSweeperSaveTool::Execute(const TSharedPtr<FJsonObject>& Request)` returns response object containing version, ok, code, and operation data. Errors are machine codes. Commandlet reads `-Request=... -Response=...` and returns 0/1/2.

- [x] Implement strict requests, catalog/list/inspect, native validation, inventory mutations, preset operations and transactional persistence.
