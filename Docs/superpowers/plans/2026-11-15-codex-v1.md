# Encyclopedia v1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship the approved enemy, weapon and ammunition encyclopedia with editable serialized WBP assets.

**Architecture:** Reuse slot-scoped item acquisition history; add slot-scoped defeated enemy kind IDs. A catalog resolves enemy classes to stable kinds. WBP panel, list row and HUD launcher contain all authored hierarchy; C++ binds events and supplies list data only.

**Tech Stack:** Unreal Engine 5.7 C++, UMG Widget Blueprints, existing CSV localization.

**Spec:** User-approved design in this chat: enemies unlock on one kill, weapons/ammunition on first acquisition; unknown enemies are silhouettes; no weakness/location, general items, factions or attachments. Weapons grouped by type then grade/name; ammunition by compatible type.

## Global Constraints
- No computer use; author assets programmatically and remove one-off generators before the single final commit.
- Widget source under Astra; actual session metadata confirms gpt-6-astra, medium reasoning.
- Widget classes use purpose plus GPT6Astra; derived WBP names end in _GPT6Astra.
- No widget-tree construction in runtime widget classes. Instantiate authored list-entry WBP through UListView.
- All player-facing text resolves existing localization keys or new six-language CSV entries.
- Preserve unrelated question/request log edits; commit only this implementation and related records.

## Review Focus
- Attachments have weapon compatibility metadata but must never enter this catalog.
- Color variants resolve to one enemy kind, specific bosses must beat parent-class matching.
- Death/abandonment preserves history; slot changes/new games clear it; old saves remain compatible.
- Modal close/travel/death restores input and pause; language refresh does not recreate hierarchy.
- Unknown entries reveal no names/descriptions; serialized panel/row/launcher trees remain editor-editable.
