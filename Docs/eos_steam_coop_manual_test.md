# EOS Steam 코옵 검증 절차

## 로컬 검증

UE 5.7 `TunaSweeperEditor Win64 Development`를 코옵 워크트리의 `.uproject`로 빌드한다. 원본 main 경로를 대신 빌드하면 코옵 변경 검증이 되지 않는다.

- `TunaSweeper.OnlineCoop` 자동화: 코드 형식·선행 0·검색 결과 검증·비동기 수명·접속 제한 등 해당 이름의 실제 테스트 결과를 확인한다.
- 코옵 UI 자동화: WBP의 부모가 `TunaSweeperOnlineCoopWidget`인지, 컴파일 오류가 없는지, 버튼과 입력칸 바인딩 및 번역이 유효한지 확인한다.
- `CoopStaging` 맵과 전용 게임 모드가 로드되고 정상 게임플레이 컨트롤러/저장 기능에 의존하지 않는지 확인한다.
- 생성기를 사용했다면 애셋 저장·재로딩 검증 후 생성기 소스를 제거하고 다시 빌드·검증한다. 빈 버튼이 겹친 기본 UUserWidget 에셋의 저장 성공만으로 UI 완료를 판정하지 않는다.

## 실제 Steam/EOS 연결

서로 다른 Steam 계정과 PC 두 대, 같은 호환 버전·Demo/Main 배포, 올바른 EOS artifact/provider 설정이 필요하다. 테스트할 계정이 해당 EOS sandbox에 접근할 수 있어야 한다.

1. 양쪽 타이틀에서 코옵 패널을 연다. 일반 싱글플레이 진입도 가능한 상태인지 확인한다.
2. 양쪽에서 연결 버튼으로 Steam/EOS 인증을 완료한다. 호스트가 방 만들기를 누르면 전용 맵의 실제 listen 연결이 준비된 후 코드가 표시되는지 확인한다.
3. 헬퍼가 표시된 8자리 코드를 입력한다. 선행 0을 그대로 유지해야 한다. 연결 완료 표시는 단순 ClientTravel 호출 시점이 아니라 실제 서버 접속 이후에 나와야 한다.
4. 호스트와 헬퍼 모두 퇴장 UI를 사용할 수 있어야 한다. 호스트 퇴장 시 헬퍼가 명확한 실패/퇴장 상태로 복구되고 싱글플레이를 사용할 수 있어야 한다.
5. 7자리·9자리·문자·전각 숫자 입력, 없는 코드, 동일 코드 중복 결과, 가득 찬 방, 호환되지 않는 버전 각각을 확인한다. 백엔드 요청이 종료된 실패는 재인증 버튼으로 준비 상태에 돌아간 뒤 코드 수정/재시도가 동작해야 한다.
6. 검색·인증·참가 중 취소 또는 패널 닫기, 요청 연속 클릭, 인증 만료, 연결 타임아웃을 확인한다. 늦은 콜백이 이미 취소한 요청으로 맵을 이동시키면 실패다. EOS 요청이 타임아웃 후에도 완료되지 않으면 새 요청을 막고 대기/재시작 안내를 표시해야 한다.
7. 로비 미가입 사용자의 직접 주소 접속과 세 번째 참가자를 거절하는지 확인한다. 코드만 안다고 인증된 참가자가 되면 안 된다.
8. 인터넷 NAT 환경을 바꿔 EOS P2P/릴레이 연결을 확인한다. LAN 또는 같은 PC 테스트 결과를 인터넷 접속 결과로 대체하지 않는다.
9. 테스트 전후 싱글플레이 슬롯/인벤토리/퀘스트 진행이 변하지 않았는지 확인한다. 별도 테스트 세이브를 사용한다.

## 결과 보고

빌드 성공, 자동화 성공, 애셋 검사 성공, 실제 서비스 연결 성공을 각각 구분한다. 서비스 설정/테스트 계정이 제공되지 않았으면 실제 Steam/EOS 및 인터넷 연결은 미검증으로 기록한다. 이 기능은 접속 기반이며 레이드 전투·아이템·진행도의 코옵 리플리케이션은 별도 작업이다.
