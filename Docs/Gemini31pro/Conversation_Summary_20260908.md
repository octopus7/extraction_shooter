# 대화 및 응답 요약 (Gemini 3.1 Pro)

본 문서는 제한적 쓰기 허용 하에 Gemini 3.1 Pro 모델과의 대화 내용을 요약하여 작성한 문서입니다.

## 1. 적 스폰 액터 분석 (`TunaSweeperRaidPlacementAnchor`)
* **핵심 구조**: 레벨 에디터에서는 위치(Transform)와 고유 ID(`PlacementId`)만 가지는 가벼운 앵커 액터를 배치합니다. 
* **데이터 연동**: 실제 소환할 적의 클래스, 확률, 장비 등은 외부 JSON 파일(`EnemyPlacements.json`, `EnemyProfiles.json`)에 분리되어 정의됩니다. 맵이 로드될 때 `TunaSweeperRaidPlacementSubsystem`이 레벨의 앵커 ID와 JSON 데이터를 매칭하여 실제 적 액터를 동적으로 스폰합니다.

## 2. 데이터 주도형(Data-Driven) 스폰 설계 평가
* **장점**:
  * **레벨 파일 경합 방지**: 바이너리 맵 파일(`.umap`)의 병합 충돌을 방지하여 레벨 디자이너와 기획자 간의 원활한 병렬 협업이 가능합니다.
  * **라이브 옵스(LiveOps) 최적화**: 앱/빌드 업데이트 없이 서버에서 JSON 파일만 갱신하여 즉각적인 밸런스 패치가 가능합니다.
  * **반복 작업(Iteration) 속도 향상 및 리플레이성**: 무거운 맵 저장 없이 기획 텍스트만 수정하여 즉시 테스트 가능하며, 시드(Seed)를 활용한 동적 변수 창출에 유리합니다.
* **단점 및 보완점**:
  * **시각적 직관성 부족**: 에디터 상에서 실제 적의 모습을 미리 보기 힘든 '블라인드 작업'이 됩니다. (에디터 전용 프리뷰 기능으로 보완 가능)
  * **ID 동기화 누락 위험**: 레벨에서 앵커를 삭제했는데 JSON 데이터가 남아있는 식의 고아(Dangling) ID 관리를 위한 자동화 검증 시스템이 필요합니다.

## 3. 데모 빌드 퀘스트 흐름 분석 (`demo.json`)
데모 빌드의 퀘스트 데이터는 총 5개(Q1 ~ Q4)로 구성되어 있으며, 벙커의 식수 문제를 해결하고 보상을 얻는 과정을 통해 게임의 코어 루프(거점 ↔ 탐색 구역)를 학습시킵니다.
* **Q1 (취수 시설 확인)**: 벙커 외부 취수 시설 정찰 후 벙커로 귀환.
* **Q2 (막힌 스크린)**: 공구 보관소에서 크로우바 확보 후 스크린 청소.
* **Q3-1 (부러진 밸브 손잡이)** & **Q3-2 (새는 벙커 배관)**: 파밍 지역에서 부품을 구해 외부와 내부를 수리하는 동시 진행 가능한 분기 미션.
* **Q4 (오늘의 보상)**: 수리 완료 후 외부 식량 창고에서 '참치캔'을 획득하고 귀환하는 데모 최종 퀘스트.

## 4. 스토브 플랫폼 제출 및 데모 빌드 마무리 논의
* **현황 및 목표**: 일주일 뒤 데모 마무리를 목표로 스토브 등급 심사용 체크리스트 작성 완료. (관련 파일: `Demo_Finalization_Checklist.md`)
* **핵심 고려 사항**: 
  * 내러티브/세이브 데이터의 데모-정식 물리적 고립(격리).
  * 스토브 SDK 최소 연동 및 전용 패키징 스크립트 작성.
  * 등급 심사용 인게임 무편집 영상(VOD) 캡처 및 설명서 준비.
* **향후 폴리싱 방향**: 퀘스트 및 시스템 기반은 완성되었으므로, 남은 기간은 익스트랙션 슈터의 텐션을 살리는 **'전투 플레이맛(타격감, 적 AI 템포 조절, 힛스탑 등)'** 퀄리티업에 전적으로 집중하는 것이 타당함.

## 5. 퀘스트 및 아이템 진행 데이터 현황 점검 (정정 업데이트)
* **데모 퀘스트(Q1~Q4) 데이터 완비**: 이전 검토에서 누락된 것으로 파악했으나, 전체 데이터를 다시 정밀 확인한 결과 `QuestDefinitions.json`과 `QuestTextStrings.csv`에 Q1부터 Q4까지의 모든 데모 퀘스트 데이터가 정상적으로 동기화(Export)되어 완벽하게 존재함을 확인했습니다. (오류 정정)
* **퀘스트 필요 아이템 데이터 완비**: Q2~Q4에 필요한 **핵심 퀘스트 아이템 데이터(크로우바, 교체용 밸브 손잡이, 방수 테이프, 참치 통조림) 역시 모두 완벽하게 세팅되어 있음**을 확인(`ItemTable.json`, `ItemNameStrings.csv`).
  * 영어/일본어 다국어 번역 완료.
  * 아이콘 에셋(`T_UIIcon_...uasset`) 지정 완료.
* **퀘스트 개별 고유 아이콘 미지원**: C++ 기반 데이터 구조체(`FTunaSweeperQuestDefinition`) 상에 퀘스트별 고유 아이콘을 직접 지정하는 기능이 부재함.

## 6. 데모 완성 최우선 과제 (인사이트)
* **엔드투엔드(End-to-End) 플레이 검증**: 현재 Q2~Q4 데이터가 인게임에 반영되지 않은 상태이므로, 타격감이나 세부 폴리싱보다 **"누락된 퀘스트 데이터를 연동하고 Q1부터 Q4 엔딩(참치캔 획득)까지 소프트락(진행 불가) 없이 플레이가 가능한지"**를 실제 플레이로 최우선 검증하는 것이 가장 시급하고 중요한 과제임.

## 7. Astra 모델 활용 계획
* `gpt-6-astra` 모델에게 지시할 작업 검증 체크리스트 문서 작성 완료. (관련 파일: `Astra_Task_Checklist.md`)
  * 항목: 채팅 환경 모델링 능력, 컴퓨터유즈 페이셜 능력, Mac/Windows 컴퓨터유즈 성능 비교 분석, 크론 표현식 패턴 처리, 전투 필(Game Feel) 개선 컴퓨터 유즈.

## 8. 기타 기술 Q&A
* **Cron 표현식 오프셋 및 범위 지정**: 
  * `1/10` : 1분부터 시작해서 매 10분마다 실행 (표준 방식).
  * `1-59/10` : 1분부터 59분까지의 '범위' 안에서 매 10분마다 실행 (결과적으로 `1/10`과 완전히 동일한 명시적/엄격한 방식).
