# 데모 빌드 마무리 및 스토브 등급심사 체크리스트

일주일 뒤부터 본격적으로 진행할 데모 빌드 마무리와 스토브 플랫폼 제출을 위한 체크리스트입니다.

## 1. 데모-정식 내러티브 고립 마일스톤 (프로젝트 필수 규칙)
- `[ ]` **데이터 세트 분리**: `Tools/QuestStudio` 내 데모 전용(demo.json)과 정식 버전 스토리 데이터를 별도의 팩으로 물리적 분리.
- `[ ]` **세이브 네임스페이스 분리**: 데모 빌드와 정식 빌드 간 세이브 파일이 섞이지 않도록 네임스페이스/경로 분리.
- `[ ]` **데이터 유출 차단**: 데모 패키징 시 미공개 정식 내러티브 데이터나 애셋이 빌드(PAK)에 포함되지 않도록 쿠킹 디렉토리 필터링 확인.

## 2. 스토브 플랫폼 연동 및 빌드 세팅
- `[ ]` **SDK 최소 연동**: 스토브 PC 클라이언트 SDK 플러그인 활성화 및 게임 시작 시 초기화(Init) 콜 로직 C++ 구현.
- `[ ]` **스토브 전용 빌드 스크립트 작성**: 기존 스팀용과 분리된 스토브 전용 패키징 스크립트(UAT) 작성.
- `[ ]` **관리자 권한 패키징 실행**: `RunUAT BuildCookRun` 실행 시 샌드박스 오류 방지를 위해 권한 상승을 통한 데모 빌드 추출 검증. (출력 경로: `Builds/Stove/Demo/Windows/...`)

## 3. 콘텐츠 폴리싱 및 QA
- `[ ]` **Q1~Q4 퀘스트 라인 QA**: 벙커 취수 시설 점검부터 참치캔 획득까지의 전체 데모 동선 플레이테스트.
- `[ ]` **JSON 기반 스폰 데이터 최종 확인**: `demo.json` 및 `EnemyPlacements.json` 데이터 유효성 검증(고아 ID 확인 등).
- `[ ]` **치명적 버그 수정 및 최적화**: 런타임 에러 로그 확인 및 메모리/프레임 드롭 구간 최적화.

## 4. 스토브 자체 등급 심사 준비물 (심사 제출용)
- `[ ]` **무편집 인게임 플레이 영상(VOD) 캡처**: 핵심 퀘스트 진행, 전투 씬, 유혈 효과(이펙트) 등이 명확히 드러나는 플레이 영상 녹화.
- `[ ]` **게임 소개 및 심사 스크린샷 캡처**: 주요 UI(인벤토리, 퀘스트 창), 전투 장면, 하우징(벙커) 스크린샷 캡처.
- `[ ]` **콘텐츠 상세 설명서 작성**: 게임물 심사 기준(폭력성 등)에 대한 소명 자료 및 플레이 방법 정리.
