# Quest Flow Simulator 계획

## 1. 목적

퀘스트 설계에 따른 이동 거리와 예상 플레이타임을 빠르게 비교하는 웹 도구를 만든다.

- 완벽한 내비게이션이나 UE 물리 재현은 목표로 하지 않는다.
- 장소 좌표와 이동 시간은 근사값을 사용하며, 약 2~3m 수준의 위치 오차는 허용한다.
- 다회 시뮬레이션은 Cloudflare Worker가 아니라 사용자 브라우저에서 실행한다.
- Cloudflare Worker는 정적 웹 제공, 인증·권한 확인, D1 데이터 조회·저장만 담당한다.
- R2는 사용하지 않는다.
- GitHub Actions를 사용하지 않고 로컬 Wrangler로 수동 배포한다.

## 2. 기술 구성안

- 프런트엔드: Svelte + TypeScript + Vite
- 지도·동선 편집: 네이티브 SVG
- 반복 시뮬레이션: 브라우저 Web Worker
- API: Cloudflare Worker
- 데이터베이스: Cloudflare D1
- 배포 도구: 프로젝트 로컬 Wrangler

React와 Konva 없이 구성하며, 지도 편집 요구가 복잡해질 때만 별도 캔버스 라이브러리 도입을 재검토한다.

## 3. Cloudflare 리소스

- Worker 이름: `quest`
- 예상 기본 주소: `https://quest.<workers.dev-subdomain>.workers.dev`
- `quest`가 현재 계정에서 이미 사용 중일 때만 `quest-tool`을 대안으로 사용한다.
- Worker는 Cloudflare 대시보드에서 미리 만들 필요가 없다. 향후 `npx wrangler deploy`가 최초 생성과 이후 업데이트를 담당한다.
- D1도 대시보드에서 미리 만들 필요가 없다. 향후 `npx wrangler d1 create quest-flow-simulator`로 생성한다.
- 계획 단계에서는 Worker와 D1 원격 리소스를 생성하지 않는다.

## 4. 데이터 공개 범위

### 비로그인

공개 체험판 퀘스트만 조회할 수 있다.

- Q1: 취수 시설 확인
- Q2: 크로우바 획득 및 스크린 청소
- Q3-1: 밸브 손잡이 확보 및 취수 시설 수리
- Q3-2: 방수 테이프 확보 및 벙커 배관 수리
- Q4: 외부 식량 창고에서 참치캔 획득 및 귀환

체험판 기준은 현재 다음 문서에 존재한다.

- `Docs/DemoDesign/01_데모_방향성과_목표.md`
- `Docs/DemoDesign/02_퀘스트_진행_트리.md`
- `Docs/DemoDesign/05_맵_세션_동선_설계.md`

목표 플레이타임은 약 10~15분, 약 3회 외출이다. 벙커에서 취수 시설까지는 단순 이동 약 40초, 교전 포함 약 1분을 초기 근사값으로 사용한다.

### 로그인

인증이 완료된 사용자에게만 다음 데이터를 제공한다.

- 본편 메인 퀘스트 M01~M20
- 현재 UE5 런타임의 구현·검증용 퀘스트 스냅샷
- 사용자가 D1에 저장한 개인 작업 상태

본편 데이터는 정적 프런트엔드 번들에 포함하지 않는다. Worker API가 catalog 목록, 상세 조회, 익스포트 요청마다 인증 여부와 접근 등급을 검사한다. 비로그인 사용자가 본편 catalog ID나 URL을 직접 입력해도 데이터 존재 여부를 드러내지 않고 404로 처리한다.

초기 운영자는 한 명이므로 인증 방식은 `ADMIN_PASSWORD` Worker Secret 기반의
단일 관리자 로그인으로 확정했다. 로그인 성공 시 32바이트 난수 세션을 만들고
D1에는 토큰의 SHA-256 해시만 저장한다. 운영 쿠키는 `Secure`, `HttpOnly`,
`SameSite=Strict`, `__Host-` prefix를 사용하고 12시간 뒤 만료한다. 로그아웃
시 D1 세션을 삭제해 기존 쿠키를 즉시 폐기한다. 같은 IP의 로그인 실패는
15분 창에서 5회까지 허용하고 이후 15분 동안 차단한다.

인증 전용 catalog와 그 편집 상태는 `localStorage`에 저장하지 않는다. 로그인
상태에서는 D1 작업공간을 우선 복원하고, 로그아웃할 때 구버전이 남긴 인증
catalog 브라우저 초안도 제거한다.

## 5. 초기 데이터 가져오기

초기 단계에서는 현재 저장소의 퀘스트 자료를 D1 초기 데이터로 변환할 수 있다.

- 체험판: `Docs/DemoDesign`의 Q1~Q4 기획을 구조화
- 현재 구현 상태: `TunaSweeper/Content/Data/QuestDefinitions.json`
- 현재 다국어 텍스트: `TunaSweeper/Content/Data/QuestTextStrings.csv`
- 본편 M01~M20: `Docs/SSOT/TunaSweeper_SSOT_Quest_Item_v0.6.md`

변환 스크립트는 원본을 직접 수정하지 않고 다음을 수행한다.

1. 필수 필드와 선행 조건을 검증한다.
2. 퀘스트·목표·문자열 키 참조 오류를 보고한다.
3. 체험판과 본편 catalog의 접근 등급을 명시한다.
4. 같은 버전을 다시 실행해도 중복되지 않도록 D1 upsert용 데이터를 만든다.
5. 원본 해시와 스키마 버전을 함께 저장한다.

장소 좌표나 행동 시간이 없는 퀘스트에는 웹 도구 전용 오버레이를 둔다. 이 근사 데이터 때문에 현재 UE5 원본 파일을 변경하지 않는다.

## 6. D1 데이터 모델 초안

### `quest_catalogs`

- `id`
- `slug`
- `title`
- `visibility`: `public` 또는 `authenticated`
- `schema_version`
- `dataset_version`
- `source_kind`
- `source_hash`
- `data_json`
- `created_at`
- `updated_at`

### `workspaces`

- `id`
- `owner_subject`
- `title`
- `catalog_id`
- `state_json`
- `revision`
- `created_at`
- `updated_at`

작업 상태는 JSON으로 저장한다. `revision`을 이용해 여러 탭이나 기기에서 동시에 저장할 때 발생하는 덮어쓰기를 감지한다.

단일 관리자의 소유자 키는 고정 `admin`을 사용한다. `admin_sessions`에는
세션 토큰 해시와 만료 시각을 저장하고, `admin_login_attempts`에는 해시된
클라이언트 키별 실패 횟수와 차단 시각을 저장한다. 비밀번호 원문은 D1이나
저장소에 저장하지 않는다.

## 7. API 경계 초안

- `GET /api/session`: 로그인 상태 확인
- `POST /api/login`: 관리자 비밀번호 확인 및 D1 세션 생성
- `POST /api/logout`: 현재 D1 세션 폐기 및 쿠키 제거
- `GET /api/catalogs`: 현재 사용자가 볼 수 있는 catalog 목록
- `GET /api/catalogs/:slug`: 공개 또는 인증 권한을 만족하는 catalog 상세
- `GET /api/workspaces`: 본인 작업 목록
- `POST /api/workspaces`: 본인 작업 상태 생성
- `PUT /api/workspaces/:id`: 본인 작업 상태 갱신
- `DELETE /api/workspaces/:id`: 본인 작업 삭제
- `POST /api/exports`: 승인된 버전의 UE5용 JSON 생성

쓰기 API는 인증된 사용자만 사용할 수 있고, 모든 조회·수정에서 `owner_subject`를 검사한다. 요청 JSON 크기와 스키마를 제한하고, SQL은 D1 prepared statement와 binding을 사용한다.

## 8. 시뮬레이션 모델

### 기본 입력

- 퀘스트 선행 조건과 분기 조건
- 목표별 장소
- 장소 좌표 또는 장소 간 근사 거리
- 이동 방식별 속도
- 전투, 상호작용, 대화, 파밍, 맵 전환에 드는 시간
- 분기 확률과 실패·재시도 확률
- 시뮬레이션 반복 횟수와 난수 시드

### 좌표 기준

- 월드 북쪽은 `+X`
- 북쪽 기준 오른쪽은 `+Y`
- UE5의 `100` 단위를 웹 도구의 `1m`로 표시
- 화면의 위쪽은 월드 `+X`
- 화면의 오른쪽은 월드 `+Y`

### 계산 범위

- 같은 구역 안에서는 직선거리 또는 사용자가 지정한 경로 거리로 계산한다.
- 맵·구역 전환은 별도 고정 시간으로 계산한다.
- 결과는 평균, 중앙값, P10, P90, 최소·최대, 총 이동 거리, 퀘스트별 소요시간을 제공한다.
- 반복 계산은 브라우저 Web Worker에서 수행해 UI 입력을 막지 않는다.
- 초기 구현에서는 정밀 충돌, NavMesh, 군중 회피, UE 프레임 단위 재현을 제외한다.

### 퀘스트 노드와 맵 장소의 분리

- `questNodes`는 선행 조건 그래프를 그리기 위한 노드와 그래프 좌표만 가진다.
- `places`는 맵상의 액터 지점 또는 원형·직사각형 영역을 표현한다.
- 퀘스트 노드는 장소로 렌더링하거나 이동 거리 계산에 사용하지 않는다.
- 장소 데이터가 없는 초기 카탈로그는 문맥 기반 임시 장소 좌표를 사용하며, 이후 장소 편집 모드에서 교체한다.

## 9. 화면 모드

화면 상단의 모드 선택 기능으로 `Desktop`과 `Pro`를 명시적으로 전환한다. 기기 자동 판별로 강제 전환하지 않는다.

선택한 모드는 로컬 사용자 설정에 저장한다. 로그인 사용자 설정 동기화는 후속 범위로 둔다. 모드를 바꿔도 퀘스트 편집 데이터, 현재 선택, 지도 확대율과 시뮬레이션 결과가 유지되어야 한다.

중앙 캔버스의 표시 모드는 별도로 세 가지를 둔다.

1. 퀘스트 체인: 퀘스트 노드와 선행 조건을 표시하고 노드 위치를 편집한다. 저장된 좌표는 자동으로 덮어쓰지 않으며, 좌표가 없는 노드 또는 사용자가 누른 자동 배치 버튼에서만 선행 조건 기준 배치를 적용한다. 수동 자동 배치는 가로 20개 노드마다 줄을 바꾸며, 콘텐츠 폭에 맞춰 캔버스를 확장하고 가로 스크롤을 제공한다. 노드 카드에는 그래프 좌표를 표시하지 않고, 식별자와 퀘스트 이름은 헤더에 배치하며, 좌우 연결 소켓은 연결 상태에 따라 회색 또는 방향별 색상으로 표시한다.
2. 선택 퀘스트 동선: 선택한 퀘스트의 실제 또는 임시 맵 동선만 읽기 전용으로 표시한다.
3. 장소 편집: 장소를 추가·이동·수정하고 지점·원형·직사각형 형태를 편집한다.

세 중앙 캔버스 모드는 공통으로 마우스 휠 확대·축소를 지원한다.

### Desktop 모드

기본 모드다.

- 기준 작업 환경: FHD 1920×1080 비율의 데스크톱 브라우저
- 상단: 프로젝트·catalog 선택, 저장 상태, 실행, 화면 모드
- 왼쪽 280~320px: 퀘스트·챕터 트리, 검색, 필터
- 가운데 가변 영역: 지도와 동선 편집
- 오른쪽 340~400px: 선택 퀘스트·장소·시간·분기 속성
- 하단 240~360px 접이식 영역: 반복 시뮬레이션 결과와 병목

4K 모니터는 OS 또는 브라우저 200% 스케일 사용을 전제로 하므로 별도 4K 레이아웃과 전용 자산을 만들지 않는다.

### Pro 모드

iPad Pro 세로 작업을 위한 선택 모드다.

- 우선 CSS viewport: 834×1194, 1024×1366
- 상단: 퀘스트명, 저장 상태, 실행, 화면 모드
- 중앙 상단 약 50~60vh: 지도와 동선 캔버스
- 중앙 하단: `퀘스트`, `속성`, `결과` 탭
- 퀘스트 트리는 전체 폭 탭 또는 슬라이드 패널
- 속성은 한 열 폼으로 배치
- 터치 대상은 최소 44px
- 드래그 기능에는 선택 후 이동, 위·아래 순서 버튼 같은 터치 대체 조작 제공
- 화면 회전 시 편집 상태는 유지하고 레이아웃만 재배치

좁은 화면에서 기능을 단순히 숨기지 않고 탭, 드로어, 접이식 패널로 옮긴다.

## 10. 미래 목표: 웹 도구를 퀘스트 SSOT로 전환

장기적으로 웹 퀘스트 도구와 D1 데이터를 퀘스트 정의의 SSOT로 삼는다.

1. 웹에서 퀘스트를 작성하고 검증한다.
2. 배포 가능한 데이터셋을 명시적으로 승인하고 버전을 고정한다.
3. 웹 도구가 `schemaVersion`, `datasetVersion`, 생성 시각, 원본 해시가 포함된 UE5용 JSON을 익스포트한다.
4. UE5 본편은 승인된 JSON을 받아 임포트한다.
5. UE5에서 수정한 퀘스트 데이터를 다시 웹으로 역수입하는 흐름은 두지 않는다.

초기에는 기존 UE5 퀘스트 파일에서 웹/D1로 가져오는 과도기 구조를 사용한다. SSOT 전환이 완료된 뒤에는 데이터 흐름을 `웹 퀘스트 도구 → 버전 JSON 익스포트 → UE5 임포트`의 단방향으로 고정한다.

## 11. 구현 단계

### 1단계: 로컬 골격

- Svelte/Vite/Worker 프로젝트 구성
- Desktop/Pro 모드 전환 골격
- 로컬 D1 마이그레이션
- 체험판 Q1~Q4 변환 및 공개 조회

### 2단계: 브라우저 시뮬레이션

- 장소와 퀘스트 단계 편집
- Web Worker 반복 실행
- 결과 통계와 동선 시각화
- 브라우저 임시 저장

### 3단계: 인증과 개인 저장

- 단일 관리자 비밀번호와 폐기 가능한 D1 세션 연결
- 로그인·로그아웃 UI 및 로그인 시도 제한
- 본편 M01~M20 API 보호
- D1 workspace 생성·수정·충돌 감지

### 4단계: 본편 데이터와 검증

- 현재 JSON/CSV 및 M01~M20 변환기
- 참조 무결성 검사
- dataset 버전 관리

### 5단계: 웹 SSOT 전환

- 승인·버전 고정 흐름
- UE5용 JSON 익스포트
- UE5 임포터 또는 Commandlet
- 기존 UE5 원본 중심 흐름 폐기

### 6단계: 수동 배포

- Wrangler dry run
- D1 원격 마이그레이션
- `npx wrangler deploy`
- 공개/인증 API 접근 회귀 테스트

## 12. 현재 확정하지 않은 항목

- 다중 사용자가 필요해질 때 도입할 외부 로그인 공급자와 계정 이전 방식
- 향후 사용자 초대·가입 범위
- 장소 좌표를 수동 입력할지 기존 맵 도구에서 가져올지
- UE5 익스포트 JSON의 최종 스키마
- 여러 사용자의 공동 편집 지원 여부

이 항목들은 구현 전에 결정하되, 공개 체험판과 인증 본편의 서버 측 분리 원칙은 변경하지 않는다.
