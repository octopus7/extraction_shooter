# QuestStudio

챕터별 퀘스트 연결을 확인하고 선행 번호를 입력하거나 연결을 해제하는 보조 도구다. 프로젝트 로컬 파일이 SSOT이며, 사용자가 가져오기·내보내기·스냅샷 저장·불러오기 시점을 결정한다.

## SSOT와 데이터 교환 방향

프로젝트 로컬 파일이 원본(SSOT)이며, `quest-pack.ko.json`과 웹/D1 스냅샷은 편집·교환용 사본이다. 다음은 확정된 교환 규칙이다.

| 데이터 | 프로젝트 원본 | 프로젝트 → 웹 | 웹 → 프로젝트 |
| --- | --- | --- | --- |
| 퀘스트 정의 | `QuestDefinitions.json` | 팩의 `nodes[].definition`으로 전달 | 정의 객체를 추출하여 반영 |
| 좌표·카드 색상 | `QuestStudioMetadata.json` | 노드의 `x`, `y`, `authoring.cardColor`로 전달 | 해당 메타데이터만 추출하여 반영 |
| 로컬라이징 문자열 | 프로젝트 문자열 원본 (`QuestTextStrings.csv` 등) | 팩의 `strings`로 전달, 웹에서는 읽기 전용 | **반영 금지: 로컬 문자열 파일을 덮어쓰지 않는다** |

`QuestDefinitions.json`의 정의 객체와 팩의 `nodes[].definition`은 같은 형식이다. 팩 생성은 정의를 감싸는 작업이고 역추출은 정의를 꺼내는 작업이며, 알 수 없는 정의 필드도 보존한다. 지역은 현재 `definition.authoring_tags`의 `chapter:N`에 포함되지만 게임 실행 판정에는 사용하지 않는다.

좌표·색상도 프로젝트에서 보존할 SSOT 데이터다. 별도 `QuestStudioMetadata.json`은 전역 퀘스트 ID를 키로 사용한다. JSON 객체 키는 `"1"`처럼 정규 십진 문자열로 저장하고 읽을 때 양의 int32 퀘스트 ID로 검증한다. 값에는 `x`, `y`, 선택적인 `cardColor`를 둔다. 색상이 없으면 기본색이며, 지역별 키나 0채움 표시 번호를 키로 사용하지 않는다. 이 정보는 런타임 퀘스트 판정에 영향을 주지 않는다.

웹의 전체 팩 내보내기와 스냅샷에는 표시·재편집에 필요한 문자열 사본이 함께 있을 수 있다. **사본에 문자열이 포함되어 있다는 이유로 역추출 시 프로젝트 문자열을 쓰면 안 된다.** 웹에서 프로젝트로 가져오는 대상은 퀘스트 정의와 좌표·색상이며, 출력 대상은 `QuestDefinitions.json`과 `QuestStudioMetadata.json` 두 파일이다.

팩 생성, 스냅샷 선택·다운로드, 검증 및 프로젝트 반영은 사용자가 명시적으로 실행한다. 툴 시작·로그인에 따른 자동 동기화는 하지 않는다. 로컬 원본을 웹 사본으로 교체하는 과정은 명시적인 적용 단계로 취급한다.

구현 상태: 현재 웹의 팩 가져오기·내보내기와 스냅샷 기능은 구현되어 있다. 위 두 프로젝트 파일을 생성·재구성하는 팩 생성/역추출 시스템과 `QuestStudioMetadata.json`의 분리 저장은 아직 구현 전이다. 이 규칙의 문서화만으로 파일 적용 기능이 추가되거나 프로젝트 데이터가 변경되지는 않는다.

## 실행과 검증

```powershell
npm ci
npm run db:migrate:local
npm run dev
```

로컬 로그인에는 Git에서 제외되는 `.dev.vars` 파일에 `ADMIN_PASSWORD`를 설정한다. 최소 10자 비밀번호를 사용한다. 실제 운영 비밀번호를 문서나 소스에 기록하지 않는다. 개발 서버 주소는 `http://127.0.0.1:5179`다.

```powershell
npm run verify
```

검증은 프로젝트 데이터 회귀 검사, 공유/서버/클라이언트 테스트, 타입 검사, 프로덕션 빌드와 Wrangler dry run을 수행한다. 콘텐츠를 읽어 시드하거나 원격 D1을 변경하지 않는다. 호환성 날짜는 설치된 Workers 테스트 런타임이 지원하는 `2026-08-06`으로 고정한다.

## 작업 흐름

1. 관리자로 로그인한다.
2. 사용자가 선택한 저작 팩 JSON을 가져오거나 D1에서 스냅샷 하나를 불러온다.
3. 챕터를 선택하고 노드를 확인한다. 다른 챕터의 직접 선행은 `다른 지역` 경계 노드까지만 보여준다.
4. 지역과 무관한 전역 숫자 퀘스트 ID로 선행을 입력한다. 기존 선행은 개별 해제할 수 있다. 없는 번호, 자기 참조 및 순환 연결은 반영하지 않는다.
5. 작업 전체를 파일로 내보내거나 새 D1 스냅샷으로 저장한다. 챕터 필터로 숨겨진 내용도 함께 보존한다.

장소, 동선, 시간 시뮬레이션은 없다. 퀘스트 본문은 읽기 전용이다. UI 문구는 `src/shared/ui-strings.ts`의 키로 관리한다.

## 교환 포맷

팩은 `schemaVersion: 1`, `nodes`, `strings`를 가진다. 노드에는 기존 `definition` 객체, `x`, `y`, `authoring` 메타데이터가 있다. 문자열은 `{key, locale, value}`이며 새 원문은 `ko`만 작성한다. 이미 가져온 다른 언어와 알 수 없는 정의 필드는 보존한다.

상세 패널의 카드 바탕 색상은 기본 회색과 가까운 은은한 팔레트다. 선택값은 `authoring.cardColor`에 `blue`, `green`, `sand`, `rose`, `purple` 중 하나로 저장한다. 기본 회색을 선택하면 해당 속성을 제거한다. 값이 없거나 알 수 없는 값이면 기존 회색 스타일을 사용하며, 불러오기만으로 팩을 변경하지 않는다. 기존 스냅샷의 데이터 갱신과 DB 마이그레이션은 없다. 이 속성은 스튜디오 표시 전용이며 런타임 정의와 선행 판정에 사용하지 않는다. 파일 교환과 스냅샷 저장은 기존 수동 작업 흐름을 따른다.

퀘스트 `quest_id`와 `required_completed_quest_ids`는 지역을 포함하지 않는 전역 정수 ID다. JSON 및 TypeScript에서는 `1`, `21`처럼 숫자로 저장하며, 허용 범위는 `1..2147483647`이다. 0, 음수, 소수, 범위 초과 및 임의 텍스트는 거부한다. 카드·상세·선행 목록과 접근성 레이블은 최소 세 자리로 표시한다 (`3` → `003`, `1000` → `1000`). `003` 입력은 정수 `3`을 찾으며 선택한 챕터와 무관하다.

기존 `schemaVersion: 1`의 정규 십진 문자열 ID (`"3"`)는 파일 가져오기와 스냅샷 불러오기 경계에서 메모리상 정수로 변환한다. 원본 파일과 D1 기록은 수정하지 않는다. 내보내기와 새 스냅샷은 숫자 JSON을 생성하며, 저장 API는 문자열 ID를 거부한다. 노드 좌표, 문자열 키, 번역, 알 수 없는 데이터는 보존한다. D1의 `quest_nodes.quest_id` TEXT 열은 조회용 문자열 투영만 유지하며 `node_json`에는 정수를 저장하므로 원격 마이그레이션이 필요 없다.

챕터는 퀘스트 정의의 `authoring_tags` 안에 있는 `chapter:N` 태그로 식별한다. UE 실행 로직은 이 태그를 사용하지 않는다. 선행관계는 `required_completed_quest_ids`에만 저장하고 후행 및 연결선을 계산한다. `authoring.prerequisitesStatus`의 `unspecified`는 원문에서 조건을 확정할 수 없다는 뜻이다.

이전 지역 접두사 ID의 팩/스냅샷은 자동으로 번호를 재배정하거나 덮어쓰지 않는다. 숫자 ID로 갱신한 전체 파일을 수동으로 가져와 새 스냅샷으로 저장한다. 문자열 키와 원문 출처 번호는 퀘스트 ID와 별개이므로 그대로 보존할 수 있다.

원문 기반 저작 팩은 실행 가능한 UE 이벤트 연결을 자동으로 만들지 않는다. 게임 파일 적용은 별도 검토한 익스포트/적용 단계다. 툴의 시작·빌드·로그인 시 파일 적용이나 네트워크 게시를 수행하지 않는다.

## 저장과 접근

작업물은 `snapshots`, `quest_nodes`, `localization_strings` 세 테이블로 구성한다. 모든 노드와 문자열은 같은 `snapshot_id`로 격리되며 일반 저장은 새 스냅샷을 생성한다. 불러온 스냅샷의 덮어쓰기는 확인 후 같은 ID의 전체 노드·문자열·팩 메타데이터를 원자적으로 교체하며, 최초 저장 시각은 유지한다. 인증은 기존 비밀번호와 관리자 세션 방식이며 인증용 세션/실패 제한 테이블이 별도로 있다.

접근 제한 본편 저작 팩은 로컬 `TunaSweeper/External/MainPayload/Authoring/QuestStudio/`에서 관리한다. 공용 소스·테스트·정적 배포 파일에는 본편 데이터를 넣지 않는다. 브라우저에서 사용자가 고른 파일만 가져온다.

## 운영 반영

Worker 이름은 `quest`, D1 바인딩은 `DB`다. 운영 비밀번호는 기존 Worker Secret을 사용한다. 새 마이그레이션은 기존 인증 테이블과 호환되도록 작성하며 이전 퀘스트툴의 테이블/콘텐츠를 자동 삭제하지 않는다.

배포 요청 시 검증된 소스를 먼저 커밋·푸시한 뒤, 운영 마이그레이션과 Worker 배포를 명시적으로 수행한다. 스키마 반영과 퀘스트 콘텐츠 임포트는 다른 작업이다. 최종 운영 동작 수용은 사용자가 확인한다.

## 노드 배치

현재 챕터의 카드를 드래그하면 기존 x/y 좌표를 변경한다. Esc 또는 포인터 취소는 이동을 취소한다. 연결 편집과 챕터 전환은 좌표를 유지하며, 전체 파일 및 새 스냅샷 저장에 포함된다. 다른 지역 경계 카드는 이동할 수 없다. 자동 정렬 버튼은 현재 챕터만 분기별로 배치하며, 불러오기나 연결 편집 시 자동 실행하지 않는다. 좌표는 definition 밖의 툴 메타데이터이며 게임 실행 조건에 사용하지 않는다.

스냅 모드는 기본 켜짐이며 드래그 중 화면 거리 8px 안의 다른 현재 챕터 카드와 x/y를 각각 맞춘다. 정렬 안내선을 표시하고 끄면 자유 이동한다. 설정은 현재 작업 세션에서 챕터 전환 후에도 유지하며 퀘스트 팩에는 저장하지 않는다. 다른 지역 경계 카드는 정렬 기준에서 제외한다.

선행이 없는 현재 챕터 카드 왼쪽의 연결 핸들을 다른 카드에 놓으면, 놓은 카드가 핸들 소유 카드의 선행이 된다. 연결 중 안내선과 대상 강조를 표시한다. 빈 곳에 놓거나 Esc/포인터 취소 시 변경하지 않는다. 숫자 입력은 계속 지원하며 동일한 자기참조·중복·순환 검증을 사용한다.

## 스냅샷 관리와 원본 파일 정보

파일 가져오기 시 브라우저 File.name과 File.lastModified를 별도 출처 메타데이터로 보관한다. lastModified는 파일 최종 수정 시각이며 생성 시각 또는 콘텐츠 버전 증명은 아니다. 스냅샷에 원본 파일명·수정 시각, 최초 저장 시각, 최종 갱신 시각을 기록한다. 기존 스냅샷의 출처는 알 수 없음으로 표시하며 추측해 채우지 않는다.

스냅샷 연결이 있는 작업에서만 불러오기와 저장 사이에 덮어쓰기 버튼을 표시한다. 파일 가져오기는 이전 스냅샷 연결을 해제한다. 저장 후 생성된 스냅샷에 연결되며, 이후 덮어쓰기에서도 원본 팩 정보를 유지한다. 삭제 모드는 불러오기 팝업 안에 있고 대상 확인 후 삭제한다. 현재 편집 중인 스냅샷 삭제 시 작업 내용과 출처는 보존하고 스냅샷 연결만 해제하여 미저장 상태로 둔다.

덮어쓰기·삭제는 불러온 revision이 일치할 때만 실행한다. 다른 창에서 갱신된 경우 409 충돌로 거부하고 현재 작업물을 유지한다. 업데이트와 삭제는 D1 트랜잭션 배치로 처리하며 읽기도 한 배치에서 수행해 스냅샷 일부가 섞이지 않도록 한다. 어떤 작업도 자동 실행하지 않는다.
